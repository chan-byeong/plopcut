# 접근성 선택 텍스트 읽기 확인 결과

Linear: STA-47 · 사양: [spec.md](spec.md) 3.1 · 항목: 체크리스트 P-16, P-17

선택 텍스트 캡처는 클립보드를 건드리지 않는 접근성 읽기를 먼저 시도하고, 값이 없으면 클립보드 폴백(백업 → `Cmd+C` → 복원)으로
넘어갑니다. 아래는 2026-10-08에 macOS 26, 터미널 앱에서 일회용 측정 도구로 확인한 결과입니다. 측정 도구는 최전면 앱에서
`AXFocusedUIElement`를 구한 뒤 `AXSelectedText`를 읽습니다. 시스템 전역 요소와 앱 요소를 둘 다 시도했습니다.

| 앱 | 시스템 전역 요소 | 앱 요소 | 결과 |
| --- | --- | --- | --- |
| Google Chrome (웹 본문 드래그 선택) | 실패 `-25204` | 성공, 101자 | 접근성 읽기 사용 |
| 메모 | 실패 `-25204` | 성공, 162자 (`AXTextArea`) | 접근성 읽기 사용 |
| Safari (웹 본문, 2회) | 실패 `-25204` | 포커스 요소 없음 `-25212` | 폴백 |
| Hyper (Electron 터미널) | 실패 `-25204` | 포커스 요소 없음 `-25212` | 폴백 |
| TextEdit, VS Code | — | — | 미확인 |

## 결론

- 시스템 전역 요소는 확인한 모든 앱에서 실패했습니다. **앱 요소(`AXUIElementCreateApplication`)만 사용합니다.**
- Chrome의 첫 시도는 포커스가 탭 버튼(`AXRadioButton`)에 있어 비었습니다. 본문에서 선택하면 읽힙니다.
- 접근성 읽기가 되지 않는 앱이 있으므로 클립보드 폴백은 필수입니다.
- Safari가 포커스 요소를 주지 않는 원인은 확인하지 않았습니다. Safari 웹 본문은 다른 접근성 API(텍스트 마커)가 필요할 수 있으나
  검증하지 않았고, 이번 범위에서는 폴백으로 처리합니다.

## 구현 후 확인

- 메모: 접근성 읽기로 캡처가 저장되었습니다.
- Safari: 접근성 읽기가 비어 클립보드 폴백으로 캡처가 저장되었고 이전 클립보드가 복원되었습니다.
