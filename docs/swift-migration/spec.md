# Plopcut Swift 구현 사양

Linear: STA-39

이 문서는 Tauri + React로 만든 Plopcut을 Swift(SwiftUI/AppKit)로 **새로 구현**하기 위한 스택 중립 사양입니다. 구현자는 레거시
코드를 번역하지 않고 이 문서와 [동작 체크리스트](behavior-checklist.md), [픽스처](fixtures/README.md)만으로 구현할 수 있어야
합니다. 레거시 구현은 관리자가 `legacy/tauri` 브랜치와 `tauri-final` 태그로 보관하며 이 공개 저장소에는 없습니다. 이 문서와 체크리스트만으로 구현할 수 있도록
썼습니다. 문서의 "근거" 열은 그 레거시 파일 이름이며, 기여자가 열어 볼 필요는 없습니다.

## 읽는 순서와 범위

1. 이 문서: 무엇을 만들지.
2. [동작 체크리스트](behavior-checklist.md): 코드에만 남아 있는 세부 동작과 확인 방법.
3. [Design.md](../../Design.md), [design-system.md](../design-system.md): 시각 기준과 SwiftUI·AppKit 구현 기준(STA-64).
   기준 이미지와 검증 캡처는 저장소에 포함하지 않으므로 두 문서의 수치와 규칙이 기준입니다.
4. 문구는 [strings.md](strings.md)의 `en`·`ko` 표가 유일한 원본입니다. 레거시 사전에서 그대로 추출한 것입니다.

이 브랜치에는 레거시 코드가 없습니다. 동작이 모호할 때만 `git show legacy/tauri:<경로>`로 파일 하나씩 확인합니다. 읽을 필요가
없는 레거시: `src/**/*.tsx`의 컴포넌트 구현, `src/App.css`, `src-tauri/src/native_toolbar.rs`, `src-tauri/src/sf_symbols.rs`.

### 범위 밖

[`AGENTS.md`](../../AGENTS.md)의 제품 경계를 그대로 유지합니다. 데이터베이스, 클라우드 동기화, OCR, AI, 협업, 모바일,
지속적 클립보드 감시, 전체 화면 녹화, 상시 하이라이트 오버레이, 원문 위치의 완벽한 복원은 명시적 요청 없이 만들지 않습니다.
클립보드는 사용자가 단축키나 메뉴로 요청했을 때만 읽습니다.

### 플랫폼

macOS 14 이상(STA-75에서 소유자가 확정. 레거시 번들은 13이었다). Apple Silicon과 Intel을 모두 지원합니다. 앱 이름은 `Plopcut`,
번들 ID는 `com.plopcut.app`입니다(STA-85). 화면·번들·DMG에 보이는 앱 이름은 `Plopcut`이고, 기본 저장 폴더·설정·로그 폴더와 로그 파일, 실행 파일 이름, 번들 ID는 호환을 위해 소문자 `plopcut`을 그대로 씁니다(PLO-107). 앱은 이전에 Notedrop이었고 번들 ID는 `app.notedrop.dev`였습니다. 번들 ID가 바뀌었으므로 예전
빌드를 쓰던 사용자는 손쉬운 사용·자동화 권한을 한 번 다시 허용해야 합니다. 예전 폴더는 1.9의 규칙으로 옮깁니다.

## 용어

| 용어 | 정의 |
| --- | --- |
| Drop | 저장한 텍스트 또는 이미지 한 건. 디스크의 폴더 하나. |
| Library | Drop을 검색하고 검토하는 메인 창 영역. |
| Collection | 사이드바에서 고르는 보기. 유형(라이브러리=전체, 텍스트, 이미지), 고정됨, 또는 태그. |
| 고정 | 사용자가 Drop을 목록 맨 위에 붙여 두는 표시. 고정 시각을 `drop.json`의 `pinnedAt`에 저장하고, 고정 해제하면 지웁니다(PLO-102). |
| Source | Drop을 가져온 앱·윈도우 제목·URL·파일 경로. 모두 선택 값. |
| 출처 키 | 출처 필터가 Drop을 묶는 단위(1.6). 웹 출처는 http(s) URL의 호스트를 소문자로 바꾸고 앞의 `www.` 하나만 뗀 값(하위 도메인 유지), 그 밖에는 앱 이름(앱 출처). 둘 다 없으면 출처 없음. 웹 출처가 있는 Drop은 앱 이름이 있으면 그 앱 출처에도 함께 속합니다(PLO-100 수정: 브라우저가 앱 목록에서 빠지지 않게). 첫째 키(웹 출처)가 대표 키입니다. |
| Note | 사용자가 Drop에 붙이는 메모. |
| Tag | 소문자로 정규화한 사용자 키워드. |
| Save Popup | 저장 전에 제목을 확인하고 노트와 태그를 입력하는 별도 창. |
| Draft | 캡처했지만 아직 저장하지 않은 내용. |
| Inspector | Library 오른쪽의 정보 패널(노트, 태그, 출처). |
| 형식 | 텍스트 Drop의 본문을 보여 주는 방식. 일반 텍스트, Markdown, 코드(언어 포함) 중 하나. 사용자가 고르지 않으면 자동 감지(2.6)로 정합니다. 원문 파일은 형식과 관계없이 같습니다(PLO-101). |

## 1. 데이터와 저장 형식 (호환성 계약)

기존 사용자의 Drop 폴더와 `settings.json`을 **수정 없이 읽고 계속 쓸 수 있어야 합니다.** 이 장의 형식은 바꾸지 않습니다.
새 키는 예전 파일을 그대로 읽을 수 있도록 더하기만 합니다(1.2의 `format`·`codeLanguage`, PLO-101).
실제 파일 모양은 [픽스처](fixtures/README.md)를 기준으로 확인합니다.

### 1.1 폴더 구조

```text
{storageFolder}/                 기본값 ~/Documents/plopcut
  drops/
    {dropId}/
      drop.json                  메타데이터
      content.md                 텍스트 Drop의 본문
      image.png                  이미지 Drop의 이미지
      note.md                    노트 (항상 생성, 비어 있을 수 있음)
```

- 텍스트 Drop: `drop.json`, `content.md`, `note.md`.
- 이미지 Drop: `drop.json`, `image.png`, `note.md`.
- `drops/` 아래의 폴더가 아닌 항목(`.DS_Store` 등)은 무시합니다.
- 원본 데이터는 읽을 수 있는 파일이어야 합니다. 데이터베이스를 쓰지 않습니다.

### 1.2 `drop.json`

UTF-8, 들여쓰기 2칸의 pretty JSON, 키는 camelCase입니다.

| 키 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | string | 폴더 이름과 같음. |
| `type` | `"text"` \| `"image"` | 저장하는 값은 이 둘뿐. 읽을 때 `"mixed"`를 만나도 깨지지 않아야 합니다(체크리스트 D-02). |
| `title` | string | 비어 있지 않음. |
| `text` | string \| null | **항상 `null`로 저장**합니다. 본문은 `content.md`에 있습니다. |
| `imagePath` | string \| null | 텍스트 Drop은 `null`, 이미지 Drop은 `"image.png"`. |
| `source` | object | 아래 참조. 항상 객체. |
| `note` | string \| null | **항상 `null`로 저장**합니다. 노트는 `note.md`에 있습니다. |
| `tags` | string[] | 정규화된 태그. |
| `createdAt` | string | 아래 시각 형식. 저장 후 바뀌지 않음. |
| `updatedAt` | string | 수정할 때마다 갱신. 형식 변경과 고정·고정 해제는 내용 수정이 아니므로 갱신하지 않습니다. |
| `format` | `"plain"` \| `"markdown"` \| `"code"` \| null | 사용자가 고른 형식(PLO-101). `null`이면 자동 감지. |
| `codeLanguage` | string \| null | `format`이 `"code"`일 때만 의미가 있는 언어 식별자(`swift`, `shell`, `json`, `javascript`, `typescript`, `python`). 그 밖에는 `null`로 씁니다. |
| `pinnedAt` | string \| null | 고정한 시각(1.4의 시각 형식). `null`이면 고정 안 됨. 이미 고정한 Drop을 다시 고정해도 처음 시각을 유지합니다(PLO-102). |

`source`의 키는 `appName`, `windowTitle`, `url`, `filePath`이며 모두 string \| null입니다. 저장할 때는 네 키를 모두
쓰고 값이 없으면 `null`입니다.

읽을 때는 누락된 키를 모두 허용해야 합니다. 필수는 `id`, `type`, `title`, `createdAt`, `updatedAt`뿐입니다. `source`가
없으면 빈 source, `tags`가 없으면 빈 배열로 취급합니다. 알 수 없는 키는 무시하되, 이 앱이 파일을 다시 쓸 때 보존할 필요는
없습니다.

`format`과 `codeLanguage`(PLO-101): 쓸 때는 두 키를 항상 쓰고 값이 없으면 `null`입니다. 읽을 때 키가 없거나 `format`이 모르는
값이면 자동 감지로 취급하고 스캔 경고는 내지 않습니다. `format`이 `"code"`가 아니면 `codeLanguage`는 무시하고, 빈 문자열도
`null`로 봅니다. `"code"`인데 `codeLanguage`가 없으면 언어 없는 코드입니다(하이라이팅 없음). 형식을 바꾸면 `drop.json`만 다시 쓰고
`updatedAt`과 `content.md`는 그대로 둡니다. 이 키를 모르는 예전 버전은 Drop을 고칠 때 키를 보존하지 않으므로 형식 선택이 사라지고
자동 감지로 돌아갑니다.
`pinnedAt`은 PLO-102에서 더한 키입니다. 쓸 때는 다른 키처럼 항상 쓰고(값이 없으면 `null`), 읽을 때 키가 없으면 `null`(고정 안 됨)로
취급합니다. 그래서 예전 버전이 만든 `drop.json`은 이전 작업 없이 그대로 읽힙니다. 반대로 예전 버전은 이 키를 모르고, 파일을 다시
쓸 때 보존하지 않으므로 예전 버전으로 Drop을 고치면 고정이 풀립니다. 저장소는 Drop을 처음부터 고정한 상태로 만들 수도
있지만(이때 `pinnedAt`은 `createdAt`과 같음) 지금 이 경로를 쓰는 화면은 없습니다(Save Popup의 "저장 후 고정"은 PLO-100 수정에서 뺌).

### 1.3 본문, 이미지, 노트

- `content.md`: 텍스트 그대로. 저장 전에 **끝의 `\r`, `\n`만** 제거합니다. 앞쪽 공백과 중간 줄바꿈은 유지합니다.
- `content.md`는 본문 편집(2.6)으로 덮어쓸 수 있습니다. 같은 규칙으로 끝 줄바꿈을 지우고, 빈 본문(공백뿐 포함)은 `empty_text`로 거부합니다.
  편집하면 `updatedAt`을 갱신하고, 원본은 따로 보관하지 않습니다(PLO-104).
- `note.md`: 노트 원문. 비었거나 공백뿐이면 화면에서는 "노트 없음"으로 취급합니다. 노트를 수정하면 파일을 항상 덮어씁니다.
- `image.png`: 클립보드 이미지를 PNG로 변환한 바이트. 이미지 Drop은 `imagePath`가 없어도 `image.png`를 기본 경로로 봅니다.
- 읽는 중 파일 하나를 못 읽어도 Drop 전체를 버리지 않고 경고(1.7)를 남깁니다.

### 1.4 ID, 시각, 제목

- 시각 형식: UTC, 소수 9자리. `createdAt`은 `2026-10-02T06:31:29.850365000Z`.
- ID: `{YYYY-MM-DD}_{HHMMSS}_{나노초 9자리}_{slug}`. 예: `2026-10-02_063129_850365000_cursor`.
  같은 ID의 폴더가 있으면 `-2`, `-3`을 이어 붙입니다.
- slug: 제목을 소문자로 바꾸고 ASCII 영숫자만 남깁니다. 그 밖의 문자 묶음은 `-` 하나로 바꾸고, 앞쪽 `-`는 쓰지 않습니다.
  48자에 도달하면 멈추고 양끝의 `-`를 제거합니다. 결과가 비면 `drop`입니다. 한글 제목은 모두 `drop`이 됩니다.
- 제목 추론(첫 번째로 비어 있지 않은 값, 앞뒤 공백 제거, 최대 80자):
  명시한 제목 → 윈도우 제목 → 앱 이름 → 본문의 첫 비어 있지 않은 줄 → `Untitled Drop`.
  이미지는 본문 대신 `Image Drop`을 쓰고, 클립보드 캡처에서 텍스트가 없으면 `{type} Drop`을 씁니다.
  Save Popup 제목 입력란의 값이 명시한 제목입니다. 입력란을 비우면 명시한 제목 없이 저장하므로 위 순서의 자동 제목이 됩니다(3.5, PLO-105).
- 폴더 이름과 ID에 `/`, `\`, `..`가 들어 있거나 비어 있는 ID는 거부합니다.

### 1.5 태그

- 입력은 쉼표로 나눕니다. 각 항목은 앞뒤 공백을 지우고, 앞쪽 `#`을 모두 지우고, 소문자로 바꿉니다.
- 빈 항목과 중복(먼저 나온 것 유지)을 제거합니다. 순서를 유지합니다.
- 디스크에서 읽을 때도 같은 규칙으로 다시 정규화합니다.
- 최근 태그: 정규화한 목록 최대 12개. 저장 후 `새 Drop의 태그 + 기존 최근 태그` 순서로 합쳐 중복을 제거하고 12개로 자릅니다.

### 1.6 목록 읽기, 검색, 정렬

- 앱 시작 시 `drops/`를 스캔해 메모리에 올립니다. 저장 후, 인스펙터 편집 후, 새로고침 동작, 다른 곳에서 저장했다는 신호를 받으면
  갱신합니다. 파일 감시는 필수가 아닙니다.
- 정렬: `createdAt` 내림차순(문자열 비교), 같으면 `id` 내림차순.
- 검색: 질의를 소문자로 바꾸고 앞뒤 공백을 지웁니다. 비면 전체. 아니면 제목, 본문, 노트, 이미지 경로, 앱 이름, 윈도우 제목,
  URL, 각 태그 중 하나에 **부분 문자열**로 들어 있으면 일치합니다(대소문자 무시).
  비교 전에 질의와 각 필드를 같은 규칙으로 접습니다: 소문자화한 뒤 유니코드 정규형 NFC로 맞춥니다. 그래서 분해형(NFD)으로
  저장된 한글은 완성형 질의로, 완성형 텍스트는 분해형 질의로 찾힙니다. 저장 파일은 정규화하지 않고 그대로 둡니다(STA-82).
- 유형 필터: 전체/텍스트/이미지. 태그 필터: 정확히 일치. 출처 필터: 출처 키의 집합. 기간: 전체, 오늘(같은 달력 날짜), 최근 7일,
  최근 30일(`createdAt ≥ 지금 − N일`). 필터는 AND로 결합하고 검색어와도 AND입니다.
- 출처 키(PLO-103): `url`을 앞뒤 공백을 지우고 URL로 읽어 스킴이 `http`/`https`이고 호스트가 있으면 웹 출처입니다. 키는 호스트를
  소문자로 바꾸고 앞의 `www.` 하나만 뗀 값입니다(`WWW.GitHub.com` → `github.com`, `developer.apple.com`은 그대로,
  `www.www.a.com` → `www.a.com`). 떼고 나서 비면 떼지 않습니다. 그렇지 않고 `appName`이 공백이 아니면 앱 출처이고 키는 앱 이름
  그대로입니다(대소문자 유지). 둘 다 없으면 출처 없음입니다. `file://`, `mailto:` 같은 URL은 웹 출처가 아니므로 앱 이름으로 갑니다.
  웹 출처와 앱 출처는 이름이 같아도 다른 키입니다.
- 출처 필터: 집합이 비면 조건을 걸지 않습니다. 그 밖에는 Drop이 속한 출처 키(웹 Drop은 웹사이트와 앱 둘) 중 하나라도 집합에 들어 있으면 통과합니다(고른 출처끼리 OR).
  출처 필터가 걸리면 출처 없는 Drop은 빠집니다.
- 고정됨 Collection: 고정한 Drop만 통과시키는 조건입니다. 유형은 전체, 태그 조건 없음. 다른 필터·검색과 AND입니다.
- `고정됨` 묶음: 날짜 그룹 앞에 둡니다. 현재 검색·Collection·필터를 통과한 Drop 중 고정한 것만 모으고, 순서는 `pinnedAt`
  내림차순(같으면 `id` 내림차순)입니다. 고정한 Drop은 날짜 그룹에 다시 나오지 않습니다. 고정한 Drop이 없으면 묶음을 숨깁니다.
  위의 기본 정렬은 바꾸지 않습니다(PLO-102).
- 날짜 그룹(달력 날짜 기준): 오늘, 어제, 지난 7일(2~7일 전), 이전. 빈 그룹은 숨깁니다.
- 선택한 Drop이 필터 결과에 없으면 결과의 첫 항목을 선택합니다. 결과가 비면 선택 없음. 첫 항목은 화면의 첫 행이므로 `고정됨` 묶음이
  있으면 그 첫 Drop입니다(PLO-102).

### 1.7 스캔 경고

폴더 하나가 깨져도 목록은 계속 만들고 경고만 모읍니다.

| 코드 | 상황 |
| --- | --- |
| `drop_scan_skipped` | 항목을 읽지 못함, `drop.json`을 읽지 못함 또는 JSON이 잘못됨. 그 Drop은 건너뜀. |
| `drop_content_unreadable` | `content.md`를 못 읽음. |
| `drop_image_unreadable` | 이미지를 못 읽음. |
| `drop_note_unreadable` | `note.md`를 못 읽음. |

`drops/`가 없으면 빈 목록입니다. `drops/` 자체를 읽지 못하면 오류(`storage_unreadable`)입니다.

### 1.8 `settings.json`

경로: `~/Library/Application Support/plopcut/settings.json` (저장 폴더 설정과 무관한 고정 위치).

| 키 | 타입 | 기본값 / 규칙 |
| --- | --- | --- |
| `storageFolderPath` | string | 기본 `~/Documents/plopcut`의 절대 경로. 공백뿐이면 거부(저장 시) 또는 기본값(읽을 때). |
| `hasCompletedFirstRun` | bool | 기본 `false`. |
| `theme` | `"system"` \| `"light"` \| `"dark"` | 기본 `system`. 읽을 때 잘못된 값은 `system`으로 보정. |
| `captureConfirmationMode` | `"modal"` \| `"instant"` | 기본 `modal`. 키가 없으면 `modal`. 읽을 때 잘못된 값은 오류. |
| `selectedTextShortcut` | string | 기본 `"Shift+Cmd+C"`. 비어 있으면 기본값. |
| `paneWidths` | `{sidebar, library}` | 기본 `{220, 330}`. 읽고 쓸 때 `sidebar`는 180–320, `library`는 300–560으로 고정. |
| `recentTags` | string[] | 기본 `[]`. 읽고 쓸 때 태그 규칙(1.5)과 최대 12개. |
| `updatedAt` | string | 저장할 때마다 갱신(1.4의 시각 형식). |

- 파일이 없으면 기본값으로 만들고 저장합니다. JSON이 잘못되면 `settings_invalid` 오류입니다. 필수 키는 `storageFolderPath`,
  `hasCompletedFirstRun`, `theme`, `updatedAt`이며 나머지는 누락을 허용하고 기본값을 씁니다.
- 쓸 때는 임시 파일에 쓰고 동기화한 뒤 이름을 바꾸는 방식으로 원자적으로 교체하고, 동시 갱신은 직렬화합니다.
- 부분 갱신: 보낸 필드만 바꾸고 나머지는 유지합니다. 검증에 실패하면 파일을 건드리지 않습니다.
- `selectedTextShortcut`은 Tauri 문법의 문자열(`Shift+Cmd+C`)로 저장합니다. 호환을 위해 이 문자열 형식을 유지하고 Swift 쪽에서
  해석합니다(체크리스트 C-06).

### 1.9 예전 Notedrop 폴더 이동

앱 이름이 Notedrop이던 시절의 폴더를 시작할 때 한 번, 설정과 로그를 열기 전에 옮깁니다. 파일 형식은 바꾸지 않고 위치만 바꿉니다.
패키지된 앱에서만 실행하며(`swift test`와 `swift run`은 개발자의 실제 폴더를 옮기지 않습니다) 구현은 `LegacyMigration`입니다.

1. `~/Library/Application Support/plopcut`이 없고 `.../Notedrop`이 폴더이면 이름을 바꿉니다.
2. `~/Documents/plopcut`이 없고 `~/Documents/Notedrop`이 폴더이면, 설정 파일이 없거나 `storageFolderPath`가 정확히
   `~/Documents/Notedrop`일 때만 이름을 바꾸고 `storageFolderPath`를 새 경로로 저장합니다. 설정 저장에 실패하면 폴더 이동을 되돌립니다.
   설정 파일을 읽을 수 없으면(`settings_invalid` 등) 폴더를 옮기지 않습니다.
3. `~/Library/Logs/plopcut`이 없고 `~/Library/Logs/Notedrop`이 폴더이면 이름을 바꾸고 `notedrop.log(.1)`을 `plopcut.log(.1)`로 바꿉니다.
4. 사용자가 지정한 다른 저장 폴더와 이미 있는 `plopcut` 폴더는 건드리지 않습니다(덮어쓰기·병합 없음).
5. 실패해도 실행을 막지 않고 오류 코드만 로그에 남깁니다. 이 경우 남은 경로를 그대로 씁니다.

## 2. 앱 구조

### 2.1 창과 진입점

| 요소 | 사양 |
| --- | --- |
| 메인 창 | 기본 1120×720, 최소 960×640. 제목 표시줄 투명, 앱 이름 제목 없음, 통합 도구 막대. Library와 Settings를 한 창에서 전환. |
| Save Popup 창 | 너비 430, 높이는 내용에 맞춤(제목 막대 아래 최소 489, STA-67, PLO-105에서 제목 입력란을 넣고, PLO-100 수정에서 `저장 후 고정`을 빼고 태그 칩 한 줄 자리를 넣고 다시 잼, 최근 태그 3개까지인 텍스트·이미지 Draft 기준). 경고·두 줄째 태그 칩·최근 태그나 `mixed`의 유형 선택이 들어가면 위쪽 가장자리를 유지한 채 아래로 커지고 내용을 자르지 않음. 화면의 보이는 영역보다 커지지 않고 그 안에 머묾. 그보다 내용이 많으면 입력 영역이 스크롤되고 저장·취소 버튼은 아래에 고정. 사용자가 크기를 조절할 수 없음, 항상 위, 열 때마다 그 Draft의 크기로 보이는 영역 중앙, Dock·전환기에 노출하지 않음, 제목 숨김, 닫으면 Draft 폐기. (레거시: 430×560 고정) |
| 메뉴 막대 항목 | "p." 마크의 단색 템플릿 이미지([5.1](#51-브랜드-마크와-앱-아이콘)), 툴팁 `Plopcut`. 좌클릭과 우클릭 모두 메뉴를 열고, 앱을 활성화하거나 메인 창을 앞으로 가져오지 않습니다(PLO-96). 메인 창은 메뉴의 `Open Library`로 엽니다. 메뉴: `Save Clipboard`(별도 창 팝업 또는 `instant`), `Open Library`, 업데이터가 있는 빌드면 구분선과 `Check for Updates`(확인 중에는 비활성, [2.9](#29-앱-안-업데이트-plo-118)), 띄운 패널이 있으면 그 뒤에 "띄워 둔 드롭" 묶음([2.8](#28-띄운-드롭-패널-plo-112)). 실패 표시 중이면 메뉴 맨 위에 오류 항목을 더합니다(아래). |
| 메뉴 막대 피드백 | 아이콘 옆에 제목 문구를 쓰지 않고 마크의 점 자리 기호로 알립니다(PLO-89, 기존 `Saved`/`Error` 900 ms 제목을 대체). **성공**: 점이 위에서 떨어져 앉고(200 ms) 체크로 바뀐 뒤, 시작부터 약 1.1초 뒤 점으로 돌아옵니다. **실패**: 아이콘이 좌우로 짧게 흔들리고(240 ms) 점 자리에 느낌표가 남습니다. 느낌표는 사용자가 메뉴를 열 때까지 유지하고, 메뉴를 열면 점으로 돌아갑니다. 실패 표시 중 메뉴 맨 위에는 `저장 실패`(`pendingFailed`) 제목과 오류 사유(지역화한 오류 문구), 구분선, `설정 열기`(`openSettings`, 메인 창의 Settings 화면)를 둡니다. 실패 중에 새 성공이 오면 성공 표시로 바뀌고 느낌표와 오류 항목을 지웁니다. '동작 줄이기'가 켜져 있으면 떨어짐과 흔들림 없이 기호만 바뀌고 시간은 같습니다. 접근성 이름과 툴팁은 상태를 함께 알립니다: `Plopcut`, `Plopcut, 드롭을 저장했습니다`(`menuBarSaved`), `Plopcut, 저장 실패`(`menuBarFailed`). 기호 모양은 [5.1](#51-브랜드-마크와-앱-아이콘). |
| 전역 단축키 | 선택 텍스트 캡처 하나. 기본 `Shift+Cmd+C`. 설정에서 바꿈. |
| 띄운 드롭 패널 | Drop 하나를 항상 위에 띄워 두는 작은 패널(PLO-112). 여러 개를 띄울 수 있고 같은 Drop은 하나만. 앱을 활성화하지 않고, 띄운 Space에만 있으며, 위치·크기는 저장하지 않습니다. 자세한 동작은 [2.8](#28-띄운-드롭-패널-plo-112). |

앱은 메뉴 막대 항목과 전역 단축키로 사용하므로 메인 창이 닫혀 있어도 캡처가 동작해야 합니다. 창을 닫았을 때 앱이 종료되는지는
레거시에서 확인하지 못했습니다(체크리스트 D-07).

### 2.2 메인 창 레이아웃

네 영역: 사이드바, 목록, 본문, 인스펙터. 수치는 [design-system.md](../design-system.md)의 "레이아웃"과 "반응형
레이아웃 및 패널 상태"를 따릅니다. 핵심 규칙:

- 사이드바 기본 220, 목록 기본 330, 인스펙터 280, 본문 최소 360. 사이드바는 창 가장자리에 붙이지 않고 8 pt 인셋과 둥근
  모서리를 가집니다. 본문은 불투명 바탕입니다.
- 사용자가 사이드바를 접기 전까지 항상 펼쳐 둡니다. 접힘 상태는 창 크기 변경과 Library/Settings 전환을 거쳐도 유지합니다
  (영구 저장하지 않음). 두 화면에서 사이드바 너비와 모양이 같습니다.
- 인스펙터는 공간이 충분하면(기본 사이드바에서 콘텐츠 폭 1176 이상) 본문 옆에 둡니다. 부족하면 접고, 토글로 오른쪽
  오버레이로 엽니다. 같은 토글이나 Escape로 닫고 Drop 목록에 포커스를 돌려줍니다(D-13). 사용자가 옆에 있는 인스펙터를 직접 접으면 그
  선택을 유지합니다.
- 구분선은 드래그로 조절하고(키보드 조절 없음, D-14), 표시 중인 실제 너비를 접근성 값으로 알립니다. 창 크기 때문에 줄어든
  표시 너비로 저장된 `paneWidths`를 덮어쓰지 않습니다. 사용자가 직접 조절했을 때만 저장합니다.
- 패널을 접거나 창 크기를 바꿔도 선택한 Drop, 검색어, 필터, 노트·태그 편집 초안은 유지합니다.

### 2.3 도구 막대

Library의 도구 막대는 왼쪽부터 창 제어, 사이드바 토글, 제목·부제목(컬렉션 이름과 `{n}개의 드롭`), (공간),
[필터 · 필터 지우기], [인스펙터 토글], [검색] 순서입니다. macOS가 `.searchable` 검색 필드를 도구 막대 맨 오른쪽에 고정하므로(macOS 26의 `DefaultToolbarItem(kind: .search)`로도 옮겨지지 않음, PLO-92) 검색이 맨 오른쪽입니다. 개별 컨트롤은 동일한 높이와
세로 중앙 정렬을 가집니다.

- 사이드바 토글은 사이드바가 펼쳐져 있을 때 사이드바 오른쪽 끝에 맞추고, 접으면 창 제어 옆으로 옮깁니다. Library와
  Settings 모두에서 동작합니다.
- 필터 지우기(`xmark.circle`)는 출처·기간 필터가 걸려 있을 때만 필터 버튼 옆에 나타납니다(2.5).
- 새로고침은 도구 막대에 두지 않고 메뉴 명령 `라이브러리 새로고침`(`refreshLibrary`, `Cmd+R`)으로 실행합니다.
- 도구 막대에 설정 버튼(Library↔Settings 전환)을 두지 않습니다. Settings는 사이드바 아래의 `설정` 행으로 열고, Library로는 사이드바의
  유형·태그 행으로 돌아갑니다.
- 선택한 텍스트 캡처 버튼은 두지 않습니다(3.1, 체크리스트 D-05).
- Settings 화면의 도구 막대에는 창 제어, 사이드바 토글, 제목 `설정`만 있습니다. 필터, 검색, 인스펙터 토글을 숨기고 `Cmd+F`를
  비활성화합니다.
- 검색: 콘텐츠 폭이 1050 pt 이상이면 입력 필드, 미만이면 아이콘. 아이콘 클릭 또는 `Cmd+F`로 필드를 열고 포커스합니다.
  Escape는 필드를 닫지만 검색어와 결과는 유지합니다. 지우기 버튼은 검색어를 비우고 전체 결과를 복원합니다. 인스펙터 오버레이와
  검색이 함께 열려 있으면 Escape가 검색을 먼저 닫고 다음 Escape가 인스펙터를 닫습니다.
- 모든 도구 막대 컨트롤은 접근성 레이블과 도움말을 가집니다(문구 `openFilters`, `clearFilters`, `showSidebar`/`hideSidebar`,
  `showInspector`/`hideInspector`, `sidebarPanelHelp`, `inspectorPanelHelp`).

### 2.4 사이드바

- 섹션 `보관함`: 라이브러리(전체), 텍스트, 이미지, 고정됨(`pin` 아이콘, PLO-102). 각 행은 개수를 오른쪽에 표시합니다.
  고정됨의 개수는 고정한 Drop 전체 수입니다.
- 섹션 `태그`: 모든 Drop의 태그를 정렬해 한 행씩. 없으면 `태그 없음`.
- 아래 고정: `설정`.
- **선택 행은 항상 정확히 하나**입니다: 유형 행, 고정됨 행, 태그 행, 설정 행 중 하나. 유형 행과 고정됨 행을 고르면 태그 필터를
  지우고(고정됨의 유형은 `all`), 태그 행을 고르면 유형을 `all`로 돌립니다. 같은 태그를 다시 눌러도 선택을 유지합니다. 설정 화면에서는 설정 행만 선택됩니다.
- 창이 활성이면 선택 행 채움은 macOS가 앱 강조색에서 만드는 `List` 기본 선택색이고 글자와 아이콘은 흰색, 비활성이면 중성색입니다(PLO-91).
  도구 막대 검색에 포커스가 가도 창 활성 상태로 취급해 색이 바뀌지 않아야 합니다.
- 행은 모두 같은 높이(32)와 같은 열 구조(아이콘, 레이블, 개수)를 씁니다. 선택하지 않은 행의 아이콘은 강조색이 아니라 보조
  회색(`.secondary`)입니다. 태그 행의 아이콘은 `number`(#)입니다. 섹션 제목은 아이콘 없는 작은 글씨입니다.

### 2.5 목록

- 헤더: 컬렉션 이름(`라이브러리`/`텍스트`/`이미지`/`고정됨`/태그 이름)과 아래에 `{n}개의 드롭`을 도구 막대 제목·부제목으로 표시합니다.
  필터 버튼과 필터가 걸려 있을 때만 나타나는 필터 지우기 버튼은 도구 막대에 있습니다(2.3). 필터는 **출처**와 **기간**만 다룹니다(유형·태그는 사이드바 담당). 적용된 필터는 (빈 상태 화면에서도) 목록 위에
  지울 수 있는 칩으로 표시하고 줄바꿈합니다. 필터 지우기는 출처와 기간을 지우고 사이드바 선택과 검색어를 유지합니다.
- 필터 팝오버(PLO-103): 위에서부터 `출처`(`source`) 제목, 출처 검색 필드(`searchSources`), `웹사이트`(`sourceWebsites`)·`앱`(`sourceApps`)
  묶음, 구분선, `기간`(`period`) 제목과 분할 컨트롤(`periodAll` 전체 / `today` 오늘 / `period7` 7일 / `period30` 30일)입니다.
  - 출처 행은 체크박스, 출처 이름, 개수입니다. 체크박스로 여러 출처를 함께 고릅니다. 빈 묶음은 숨깁니다.
  - 개수는 출처 필터를 뺀 나머지 조건(Collection, 검색, 기간)을 적용한 결과로 셉니다. 개수가 0인 출처는 고른 것만 남깁니다.
    웹 Drop은 웹사이트 묶음과 앱 묶음(예: `Google Chrome`)에 모두 셉니다(PLO-100 수정).
    묶음 안에서는 개수 내림차순, 같으면 이름 오름차순(`localizedStandardCompare`)입니다.
  - 출처 검색은 앞뒤 공백을 지운 검색어가 이름에 부분 문자열로 들어 있는 출처만 남깁니다(대소문자 무시, `localizedStandardContains`). 남는 출처가 없으면
    `noMatchingSources`를 보여 줍니다. 검색어는 팝오버를 닫으면 지웁니다.
- 칩: 고른 출처마다 `출처: {source}`(`sourceChip`) 칩 하나, 기간이 걸려 있으면 기간 칩 하나(`anyTime`/`today`/`last7`/`last30`
  문구). 칩을 누르면 그 출처(또는 기간)만 해제합니다. 칩의 접근성 이름은 `필터 제거 {칩 문구}`입니다.
- `이 출처의 드롭 보기`(`showSourceDrops`): 우클릭 메뉴와 인스펙터 출처 칸(2.7)에 있습니다. 누르면 Collection을 라이브러리로 바꾸고
  출처 필터를 그 Drop의 대표 출처 키 하나로 바꿉니다(웹 Drop은 웹사이트). 기간과 검색어는 그대로 둡니다. 출처 없는 Drop에서는 비활성입니다.
- 맨 위 `고정됨` 묶음(1.6), 날짜 그룹 제목(`오늘`, `어제`, `지난 7일`, `이전`)과 행. 고정됨 Collection에서는 묶음 제목 없이 고정
  시각순으로만 보입니다. 고정한 행은 제목 오른쪽, 시각 앞에 파란(강조색) `pin.fill` 아이콘이 붙고, VoiceOver는 행 이름 뒤에
  `고정됨`(`pinned`)을 읽습니다. 고정·고정 해제 뒤에도 선택은 그 Drop에 남습니다. 고정됨 Collection에서 고정 해제한 Drop은
  목록에서 빠지므로 1.6의 선택 규칙을 따릅니다. 행: 출처 앱 아이콘(없으면 공통 아이콘), 제목, 시각(시:분), 미리보기
  한 줄(본문 → 노트 → 윈도우 제목 → URL → 이미지 경로 → 앱 이름 → 모두 없으면 `No preview`. 이 문구는 레거시에서 영어로 고정), 앱 이름, 태그 최대 3개와 `+n`.
  태그는 `#design`처럼 앞에 `#`을 붙여 보조 회색(`.secondary`)으로 표시합니다. `#`은 표시용이며 저장 값(1.5)에는 넣지 않습니다.
- 로딩, 결과 없음(`noMatches`), Drop 없음, 스캔 경고를 서로 구분해 표시합니다.
- Drop 없음(빈 Library): 컬러 마크(72 pt, [5.1](#51-브랜드-마크와-앱-아이콘)), 제목 `noDropsTitle`, 안내 `noDropsShortcutHint`, 현재
  선택 텍스트 단축키를 키캡으로(기본 `⇧` `⌘` `C`, 설정 값을 따름), 클립보드 저장 안내 `noDropsClipboardHint`를 세로로 가운데
  둡니다. 키캡 묶음은 단축키 전체를 읽는 접근성 이름 하나를 가집니다. 이 상태에서는 필터와 인스펙터 토글을 비활성화합니다.
- 키보드: 위/아래 화살표로 선택 이동(경계에서 멈춤), Enter로 제목 입력에 포커스, Escape로 목록에 포커스, `Cmd+Backspace`로
  삭제 확인, `Shift+Cmd+P`로 선택한 Drop 고정·고정 해제, `Cmd+E`로 본문 편집(2.6), 우클릭 메뉴(맨 위 고정/고정 해제 `⇧⌘P`, 편집 `⌘E`(이미지 Drop에서는 비활성, PLO-104), 출처 열기(URL이 있을 때),
  이 출처의 드롭 보기(출처가 없으면 비활성), 내용 복사(텍스트일 때), Markdown 내보내기, 구분선, 휴지통으로 이동 `⌘⌫`). 단축키가
  있는 항목은 메뉴에 단축키를 표시합니다. `Shift+Cmd+P`는 메뉴 명령이며 Library에 선택한 Drop이 있으면 켜집니다(설정 화면에서는 꺼짐).
  `Cmd+E`(`편집`)도 메뉴 명령이며 Library에 선택한 텍스트 Drop이 있고 본문 편집 중이 아닐 때 켜집니다.
- 목록에 포커스가 없을 때 선택 행은 중성색으로 약해집니다(AppKit 테이블 동작). STA-38에서 도입했고 실제 앱에서는 확인하지
  못했습니다.

### 2.6 본문

- 상단: 유형 표시(`텍스트 드롭`/`이미지 드롭`), 제목 입력, 동작 버튼 줄(본문 편집 중에는 편집 줄, 아래 "본문 편집").
- 동작 버튼은 아이콘만 있는 38×26 pt 버튼입니다(PLO-102). 순서는 고정(`pin`, 고정한 Drop에서는 눌린 상태와 `pin.fill`) ·
  편집(`pencil`, `⌘E`, 이미지 Drop에서는 비활성, PLO-104) · 화면에 띄우기(`macwindow.on.rectangle`, 띄운 Drop에서는 눌린 상태, [2.8](#28-띄운-드롭-패널-plo-112)) · 출처 열기(`arrow.up.right.square`, URL 없으면 비활성) ·
  Markdown 내보내기(`square.and.arrow.down`) | 구분선 | 휴지통으로 이동(`trash`, 빨강)입니다. 툴팁은 `이름 (단축키)`(단축키가 없으면 이름만),
  접근성 이름은 버튼 이름(고정한 Drop에서는 `고정 해제`)입니다. 더 보기 버튼은 두지 않습니다.
  모양은 시안 MainFeatures를 따릅니다(PLO-100 수정): 버튼 사이 6 pt, 모서리 7 pt, 컨트롤 배경에 1 pt 테두리(전경색 12%),
  호버 때 테두리 22%·채움 5%, 누름 때 채움 10%, 고정한 Drop의 고정 버튼은 강조색 테두리 35%·채움 10%와 강조색 아이콘,
  아이콘 13 pt, 휴지통 앞 구분선은 1×16 pt. 비활성 버튼은 40% 불투명도입니다. 툴팁은 시스템 툴팁 대신 0.3초 호버 뒤 버튼 아래
  6 pt에 가운데 맞춘 작은 말풍선(11 pt, 모서리 5 pt, 1 pt 테두리, 그림자)으로 그리고, 누르거나 커서가 벗어나면 숨깁니다.
- 제목은 항상 보이는 인라인 이름 변경 필드입니다. 글자 위치는 고정이고 편집할 때만 필드 모양이 나타납니다. Return은 확정하고
  Escape는 편집 시작 때의 제목으로 되돌립니다. 둘 다 편집을 끝내고 포커스를 목록에 돌려줍니다. (STA-38에서 도입, 실제 앱 미검증.
  서체관리자·Finder의 이름 변경 동작을 기준으로 합니다.)
- 본문: 텍스트 Drop은 형식(아래)에 맞게 렌더링한 텍스트(선택·복사 가능), 이미지 Drop은 이미지 미리보기, 이미지를 못 읽으면 대체 표시.

#### 형식과 렌더링 (PLO-101)

- **형식 버튼**: 텍스트 Drop의 유형 표시 옆에 현재 형식 이름과 `▾`를 단 메뉴 버튼(`Markdown ▾`)을 둡니다. 이름은 `일반 텍스트`,
  `Markdown`, 코드면 언어 이름(`Swift`, 언어가 없으면 `코드`)입니다. 접근성 이름은 `형식: {이름}`입니다. 이미지 Drop에는 없습니다.
- **형식 메뉴**: `자동 감지 ({감지 결과})`, 구분선, `일반 텍스트`, `Markdown`, `코드 ▸` 언어 하위 메뉴(Swift, Shell, JSON,
  JavaScript, TypeScript, Python). 현재 값에 체크 표시를 합니다. 자동 감지가 아닌 값을 고르면 `drop.json`의 `format`·`codeLanguage`에
  저장하고, `자동 감지`를 고르면 두 키를 `null`로 지웁니다. 저장에 실패하면 이전 형식을 유지하고 오류를 상태 메시지로 보여 줍니다.
- **자동 감지** (`FormatDetection`, 순수 함수, 사례는 `FormatDetectionTests`). 사용자가 저장한 선택이 있으면 그것을 씁니다. 없으면 이 순서:
  1. 앱 이름이 Terminal·터미널·iTerm·iTerm2면 코드(Shell), Xcode면 코드(Swift).
  2. 앞뒤 공백을 뺀 전체가 유효한 JSON 객체나 배열이면 코드(JSON).
  3. Markdown 신호가 뚜렷하면 Markdown. 닫힌 펜스 코드 블록, `[글](주소)` 링크, 표(`|`가 있는 머리글 줄 바로 다음에 칸 수가 같은
     구분 줄 `| --- | :-: |`, PLO-107)가 하나라도 있거나, 다음 종류 중 두 가지 이상이
     있으면 뚜렷하다고 봅니다: 줄 첫머리 `#`~`######` 뒤 공백이 오는 제목, 목록 줄(`-`, `*`, `+`, `1.` 뒤 공백), 인용 줄(`> `),
     `**굵게**`·`__굵게__`, `` `인라인 코드` ``.
  4. 나머지는 일반 텍스트. `*`나 `#`이 한두 개 섞인 평문은 일반 텍스트입니다.
- **Markdown 렌더링**: [swift-markdown](https://github.com/swiftlang/swift-markdown) 0.9.0으로 파싱합니다. 제목(1–6단계), 문단,
  굵게·기울임·취소선, 인라인 코드, 순서·비순서 목록(중첩, 시작 번호, 체크박스는 `☐`/`☑` 글자), 인용, 구분선, 링크, 펜스·들여쓰기 코드 블록, 표를 렌더링합니다.
  문단 안의 줄바꿈 하나도 줄바꿈으로 보여 줍니다(클립보드 글의 줄 모양 유지).
  이미지, HTML 블록과 인라인 HTML은 원문 Markdown 텍스트 그대로 보여 줍니다. 이미지는 로컬·원격 모두 불러오지 않습니다.
  링크는 `http`, `https`, `mailto`만 누를 수 있고 기존 URL 열기 경로(기본 브라우저)로 엽니다. 그 밖의 주소는 글자만 보여 줍니다.
- **표**(GFM, PLO-107): 머리글 줄은 굵게(semibold), 옅은 바탕으로 구분하고 행 사이에 구분선을 둡니다. 열 정렬은 구분 줄의
  `:--`(왼쪽)·`:-:`(가운데)·`--:`(오른쪽)을 따르고 없으면 왼쪽입니다. 셀 안의 굵게·기울임·취소선·인라인 코드·링크는 문단과 같게
  렌더링합니다. 머리글보다 칸이 적은 행은 빈 칸으로 채우고 많은 칸은 버립니다(GFM 규칙). 셀 글은 줄바꿈하지 않고, 표가 본문보다
  넓으면 코드 블록처럼 가로로 스크롤합니다. 둥근 테두리는 코드 블록과 같습니다.
- **일반 텍스트**: 지금처럼 원문 그대로(선택·복사 가능).
- **코드**: 본문 전체를 코드 블록 하나로 보여 줍니다.
- **코드 블록**: 고정폭 글꼴, 옅은 바탕의 둥근 상자, 위쪽 줄에 언어 이름(펜스에 언어가 없으면 `코드`)과 `코드 복사` 버튼
  (`doc.on.doc`, 누르면 잠깐 `checkmark`). 복사 버튼은 코드 블록의 코드만(끝 줄바꿈 제외) 클립보드에 씁니다. 긴 줄은 가로로
  스크롤합니다. 문법 하이라이팅은 [HighlighterSwift](https://github.com/smittytone/HighlighterSwift) 3.1.0(highlight.js 11, 앱 안에
  포함, 네트워크 없음)이고 테마는 라이트 `github`, 다크 `github-dark`를 그대로 씁니다(Xcode 색에 맞추지 않음, 2026-10-18 소유자 확인).
  언어 식별자 `shell`은 highlight.js의 `bash`로 넘깁니다. 하이라이터가 모르는 언어면 색 없이 고정폭으로 보여 줍니다.
- **접근성**: 제목은 제목 역할과 단계로, 목록 항목은 번호나 글머리를 앞에 붙여 읽습니다. 목록 전체는 `목록`, 인용은 `인용`, 표는 `표`(`markdownTable`)라는 이름의
  묶음입니다. 코드 블록은 `코드 블록, {언어}` 묶음으로 읽고, 복사 버튼 이름은 `코드 복사`입니다.
- 렌더링 결과는 같은 본문·형식·외형이면 다시 계산하지 않도록 캐시합니다(Drop 사이를 빠르게 오갈 때 지연 방지).
- **선택 범위의 한계(알려진 제약, PLO-100 리뷰)**: 일반 텍스트와 코드 형식은 본문이 한 덩어리라 전체를 끌어 선택할 수 있습니다.
  Markdown은 블록(제목, 문단, 목록 항목, 인용, 코드 블록)마다 따로 그리므로 선택이 한 블록 안에서만 됩니다. 여러 문단에 걸쳐
  끌어 선택하거나 본문 전체를 `⌘A`로 고를 수 없습니다. 여러 블록을 복사하려면 `편집`으로 원문을 열거나 형식을 `일반 텍스트`로
  바꿉니다. 블록 사이 선택은 본문 전체를 NSTextView 하나로 그려야 하는데, 제목 역할·단계와 코드 블록의 복사 버튼·가로 스크롤을
  유지하려면 렌더러를 다시 짜야 해서 이번 범위에서 뺐습니다(user story 16의 일부 선택은 블록 안에서만 충족).
#### 본문 편집 (PLO-104)

텍스트 Drop의 원문(`content.md`)을 앱 안에서 고칩니다. 자동 저장이 아니라 `완료`/`취소`로 끝내는 명시 저장입니다.

- **시작**: 동작 버튼 `편집`, 우클릭 메뉴 `편집`, 메뉴 명령 `Cmd+E`. 이미지 Drop(그리고 본문을 읽지 못한 텍스트 Drop)에서는 비활성입니다.
  시작하면 그 Drop을 선택하고 편집기에 포커스를 줍니다.
- **화면**: 유형 줄 끝에 `· ● 편집 중`(`editingBody`)을 붙입니다. 동작 버튼 줄 자리에 안내 문구 `editBodyHint`와 `취소`(`cancel`)·
  `완료`(`done`, 강조색 버튼) 버튼 줄을 둡니다. 렌더링한 본문 자리에 편집기를 두고, 아래에 변경이 있으면 `● 변경됨`(`bodyChanged`), 오른쪽에
  `⌘↩ 완료 · esc 취소`(`editBodyShortcuts`)를 둡니다. 저장에 실패하면 이 줄에 오류를 빨갛게 보여 줍니다.
- **편집기**: 원문 그대로의 일반 텍스트, 고정폭 글꼴(본문 크기), 왼쪽에 줄 번호(논리 줄 기준, 흐린 색), 긴 줄은 줄바꿈합니다. Markdown 기호는 흐린 색
  (`secondaryLabelColor`)으로 보입니다: 줄 첫머리 제목 `#`, 목록 기호(`-`, `*`, `+`, `1.`), 인용 `>`, 펜스 줄(```` ``` ````와 언어 이름) 전체,
  `**`/`__`/`*`/`_`/`~~` 강조 기호, 인라인 코드의 `` ` ``. 흐린 색은 화면 표시용이고 저장하는 텍스트에는 영향이 없습니다. 형식 선택과 관계없이
  같은 규칙을 씁니다. 입력기 조합 중의 글자는 건드리지 않습니다(I-04). 접근성 이름은 `editBodyField`입니다.
- **완료**(`완료` 버튼, `Cmd+Return`): 확인 없이 `DropUpdate.text`로 `content.md`를 덮어쓰고 `updatedAt`을 갱신합니다(1.3). 변경이 없으면 쓰지
  않고 끝냅니다. 끝나면 저장된 본문을 그 Drop의 형식(위)대로 다시 렌더링하고, 목록 미리보기와 검색 색인에도 바로 반영합니다.
  - 빈 본문(공백뿐 포함)이면 쓰지 않고 편집기를 연 채 `emptyBody` 오류를 보여 줍니다.
  - 저장이 실패하면 편집기를 연 채 입력한 텍스트를 유지하고 오류(`ErrorText`)를 보여 줍니다. 다시 `완료`를 누르면 재시도합니다.
  - 쓰기가 끝날 때까지(앞선 쓰기 뒤에 줄 서 있거나 저장소가 느려도) 편집기는 텍스트를 보여 주되 입력을 받지 않고 `완료`도 비활성입니다.
    보낸 텍스트와 남는 텍스트가 늘 같아서, `완료` 뒤에 친 글자가 몰래 사라지지 않습니다. 실패하면 다시 입력할 수 있습니다.
- **취소**(`취소` 버튼, 편집기에 포커스가 있을 때 Escape): 제목·노트 입력란의 Escape는 그 입력란의 동작을 그대로 하고, 편집 중에는 인스펙터 오버레이를 Escape로 닫지 않습니다(토글로 닫음). 변경이 없으면 바로 끝냅니다. 변경이 있으면 확인 대화상자 `discardChangesTitle`(본문 `discardChangesBody`,
  버튼 `discardChanges`(파괴적)·`keepEditing`(취소))를 띄웁니다. 버리면 편집을 끝내고 원래 본문을 보여 줍니다.
- **떠나기**: 변경이 있는 채로 다른 Drop을 고르거나 Collection(사이드바 행, `이 출처의 드롭 보기`)을 바꾸면 같은 확인을 띄우고, 그동안 선택과
  Collection을 바꾸지 않고 보류합니다. 버리면 보류한 변경을 적용하고, `계속 편집`이면 보류한 변경을 버립니다. 변경이 없으면 확인 없이 편집을
  끝내고 바로 바꿉니다. 검색어·필터가 바뀌어 편집 중인 Drop이 목록에서 빠져도 편집하는 동안은 선택을 그 Drop에 둡니다. Save Popup으로 새 Drop을 저장해도 편집하는 동안은 새 Drop으로 선택을 옮기지 않습니다. 보류하는 동안 목록과 사이드바의 강조는 원래 행에 남습니다.
  `완료`의 쓰기가 끝나기 전에 떠나기(다른 Drop, Collection, `취소`)를 요청하면 확인 없이 보류했다가, 성공하면 그때 바꾸고, 실패하면 보류한
  변경을 버리고 편집기를 입력한 텍스트와 오류와 함께 열어 둡니다. 보류 중에 다시 요청하면 마지막 요청만 남습니다.
- **종료**(`Cmd+Q`, 메뉴 막대 `종료`): 진행 중인 `완료` 쓰기는 다른 자동 저장처럼 끝날 때까지 기다립니다. 그 뒤 변경이 남은 본문 초안이 있으면
  자동으로 저장하지 않고 시스템 알림으로 묻습니다: 제목 `quitBodyDraftTitle`, 본문 `quitBodyDraftBody`, 버튼 `save`(기본, Return)·
  `dontSave`·`cancel`(Escape). 저장은 `완료`와 같은 쓰기 경로를 따르고 성공해야 종료를 이어 갑니다. 실패하면 종료를 취소하고 편집기를 오류와
  함께 열어 둡니다. 저장 안 함은 쓰지 않고 초안을 버린 뒤 종료를 이어 가고, 취소는 종료를 취소하고 초안을 그대로 둡니다. 그다음 남은 제목·노트·태그
  자동 저장(2.7)을 모두 쓰고 종료합니다. 그 쓰기가 실패하면 첫 종료는 취소하고 `saveFailed`를 알리며, 15초 안에 다시 종료하면 그대로 종료합니다.
- **자동 저장과의 관계**: 제목·노트·태그 자동 저장(2.7)은 편집 중에도 그대로 동작합니다. 본문 저장은 자동 저장과 같은 쓰기 순서(한 번에 하나)를
  따르고 `text`만 보내므로, 서로의 초안과 상태를 덮어쓰지 않습니다.
- 원본 보관, 수정 기록, 되돌리기, 실시간 미리보기, 서식 도구 막대는 없습니다. 인스펙터에 "원본 보관됨" 같은 표시를 두지 않습니다.

- 선택 없음: 안내 문구 `selectHint`.
- 삭제는 확인 시트를 거쳐 폴더 전체를 휴지통으로 옮깁니다. 휴지통 이동 후에도 폴더가 남아 있으면 실패입니다.

### 2.7 인스펙터

- `정보` 제목, `노트`(여러 줄 입력, 저장 상태 표시: `automaticSave`/`changesPending`/`saving`/`saved`/`saveFailed`), `태그`(입력 + 등록 버튼 + 삭제 가능한
  칩 목록 + 힌트), `출처`(앱 아이콘, 앱 이름, `저장 {시각}`, 작은 버튼 `이 출처의 드롭 보기`(2.5, 출처가 없으면 비활성))와 `출처 상세 정보` 펼침(윈도우 제목, 수정 시각, URL, 파일 경로 중
  **있는 것만**, URL과 파일 경로는 복사 버튼).
- 자동 저장: 편집 후 600 ms 디바운스, 입력 필드를 떠날 때(blur) 즉시 저장. 저장이 실패한 상태에서는 blur로 재시도하지 않고
  `다시 시도` 버튼을 줍니다. 제목이 공백이면 저장하지 않고 `blankTitle` 오류를 표시합니다. 다른 Drop을 선택하면 편집 상태를
  초기화합니다. 저장 응답이 도착했을 때 이미 다른 Drop이거나 더 새 편집이 있으면 그 응답을 반영하지 않습니다.
- 띄운 패널과 공유(PLO-114): 편집 상태는 Drop마다 하나입니다. 인스펙터와 그 Drop의 띄운 패널이 같은 노트 초안과 저장 상태를 보고,
  한쪽 입력이 다른 쪽에 바로 보이며 자동 저장은 한 번만 일어납니다. 위 규칙(디바운스, blur 저장, 실패 뒤 `다시 시도`, 오래된 응답
  무시)이 패널에도 같고, 저장 실패는 양쪽에 같은 `다시 시도`로 보입니다. 인스펙터에서 다른 Drop을 고르면 인스펙터만 바뀌고 패널의
  입력은 그대로 이어지며, 저장 대기 중인 입력은 그때 바로 저장합니다. 패널이 있는 Drop의 저장 실패는 알림 대신 패널에 보이고, 패널을
  닫은 뒤의 실패는 다른 백그라운드 저장처럼 알림으로 보입니다.
- 태그 입력: Enter 또는 쉼표로 등록. **한글 등 입력기 조합 중에는(`isComposing` 또는 keyCode 229) 등록하지 않습니다.**
  이미 있는 태그를 추가하면 `tagAlreadyAdded` 안내. 등록 뒤 입력창에 포커스를 유지합니다. Escape는 입력창을 떠납니다.
- 본문 편집(2.6) 뒤에는 `출처 상세 정보`의 수정 시각이 새 `updatedAt`을 보여 줍니다. 원본 보관이나 수정 기록 표시는 없습니다(PLO-104).
- 등록 전 초안과 삭제 가능한 태그 칩을 시각적으로 구분합니다. 칩은 `#design`처럼 `#`을 붙여 표시합니다(PLO-89).

### 2.8 띄운 드롭 패널 (PLO-112)

다른 앱에서 작업하면서 Drop을 참고하고 노트를 적도록 Drop 하나를 작은 패널로 화면에 띄워 둡니다. 시안은 디자인 캔버스
"드롭 띄우기" 줄(FloatPanel, FloatingDesktop, FloatingStates)이고, 아래 결정(2026-10-27)이 시안과 다르면 아래를 따릅니다.

- **창 종류**: 비활성화 패널(`NSPanel`, `.nonactivatingPanel`). 패널을 누르거나 입력해도 Plopcut을 활성화하지 않으므로 쓰던 앱이
  앞에 남고 메인 창이 앞으로 오지 않습니다. 창 수준은 항상 위(floating)입니다. 띄운 Space에만 있고 다른 Space나 전체 화면 앱
  위로 따라가지 않습니다. Mission Control에 보이므로 거기서 다른 Space로 끌어 옮길 수 있습니다. Dock·앱 전환기·윈도우 메뉴에 노출하지 않습니다.
- **제목 막대**: 시스템 유틸리티 막대(작은 닫기 버튼만, 최소화·확대 없음, 가운데 제목 = Drop 제목). 오른쪽에 아이콘 버튼 두 개(각 22 pt, 간격 4 pt, 라벨 색):
  `라이브러리에서 열기`(`openInLibrary`, `arrow.up.forward.app`)와 `접기`/`펼치기`(`collapsePanel`/`expandPanel`, `chevron.up`/`chevron.down`).
  제목 막대를 더블클릭해도 접고 펼칩니다(시스템의 더블클릭 동작 대신). 시안의 직접 그린 32 pt 막대와 빨간 닫기 점은 쓰지 않습니다.
- **바탕**: 시스템 반투명 재질(제목 막대 아래까지). 다크 모드, 투명도 줄이기, 대비 증가는 시스템이 처리합니다.
- **반투명**: 커서가 패널 밖에 있고 패널이 키 창이 아니면 패널 전체를 불투명도 0.78로 낮춥니다. 커서가 들어오거나 패널이 키 창이면
  불투명. 투명도 줄이기가 켜져 있으면 항상 불투명. 바뀔 때 0.15초 동안 전환하고, 동작 줄이기가 켜져 있으면 바로 바꿉니다.
- **크기**: 폭 기본 300 pt, 끌어서 240 pt 이상(최대 제한 없음, PLO-117). 높이는 열 때 내용에 맞추되 현재 화면 보이는 영역 높이의 60%를 넘지 않고, 넘치면 본문만
  스크롤합니다. 사용자가 높이도 바꿀 수 있습니다(최소 120 pt). 이미지 Drop은 이미지를 폭에 맞추고 비율대로 높이를 정하며, 최대 높이를
  넘으면 이미지를 축소합니다(스크롤 없음).
- **위치**: 커서가 있는 화면의 보이는 영역 오른쪽 위에서 24 pt 안쪽에 엽니다. 이미 띄운 패널이 있으면 띄운 개수만큼 왼쪽 아래로
  24 pt씩 어긋나게 엽니다. 어긋난 자리가 화면을 벗어나면 화면 안으로 당깁니다.
- **접기**: 제목 막대만 남기고, 펼치면 접기 전 높이로 돌아옵니다. 위쪽 가장자리는 그대로입니다. 접힌 동안 높이는 바꿀 수 없습니다.
- **내용**: 위에서부터 본문, 구분선, 노트. 텍스트 Drop의 본문은 2.6의 렌더링(형식 선택 반영)을 읽기 전용으로 보여 주고 선택·복사와
  코드 블록 복사가 됩니다. 제목 크기는 패널에 맞춰 한 단계씩 줄입니다. 노트 섹션은 `노트` 제목과 노트 입력란입니다(편집과 저장은
  아래 "노트", PLO-114). 시안의 하단 출처 줄은 넣지 않습니다. Library에서 본문·제목·형식·노트가 바뀌면 패널이 새 값을 보여 줍니다.
- **노트**(PLO-114): Library 인스펙터와 하나의 편집 상태를 함께 씁니다(2.7 "띄운 패널과 공유"). 저장 상태 문구는 `노트` 제목 오른쪽에
  있고, 입력란은 세 줄 높이(64 pt)이며 넘치면 입력란 안에서 스크롤합니다. 빈 노트는 `noNote` 자리 표시자를 보여 줍니다. 패널이 열릴 때
  입력란이 키 초점을 가져가지 않습니다. esc는 노트를 바로 저장하고 키 초점을 돌려줍니다(패널은 남음). 한글 조합 중 esc는 조합만 끝냅니다.
  패널을 닫을 때(닫기 버튼, `⌘W`, Drop이 사라져서) 저장 대기 중인 노트를 디바운스를 기다리지 않고 저장하고, 앱을 끌 때는 다른 편집처럼
  모두 저장한 뒤 끝냅니다.
- **닫기**: 닫기 버튼, 패널이 키 창일 때 `⌘W`. esc는 패널을 닫지 않고 키 초점만 돌려줍니다(Plopcut이 비활성이면 쓰던 앱, 활성이면 메인 창). 띄운 Drop이 휴지통으로 가거나 Library를 다시 읽었을 때 사라지면 그 패널을 닫고, 저장 폴더를
  바꾸면 모든 패널을 닫습니다. 따로 알리지 않습니다.
- **라이브러리에서 열기**: 메인 창을 열고 그 Drop을 선택합니다. 필터가 그 Drop을 가리면 검색과 필터를 지우고 라이브러리 Collection으로
  바꿉니다(3.5 저장 뒤 선택과 같음).
- **저장하지 않음**: 띄운 패널 목록, 위치, 크기, 접힘 상태는 어디에도 저장하지 않습니다(시스템 창 복원도 끔). 앱을 끄면 모두 닫히고,
  다시 띄우면 기본 위치·기본 크기로 열립니다. 저장 형식(1장)과 `settings.json`은 바뀌지 않습니다.
- **여는 곳**: 드롭 화면의 `화면에 띄우기` 버튼(2.6, PLO-115). 띄우지 않은 Drop이면 툴팁 `화면에 띄우기`(`floatDrop`), 띄운 Drop이면
  숨김 여부와 관계없이 눌린 상태와 툴팁 `띄운 창 닫기`(`closeFloating`)입니다. 보이는 패널은 닫고, 숨긴 패널은 다시 보이고 앞으로 가져옵니다.
  전역 단축키, 우클릭 메뉴, Save Popup에서는 띄우지 않습니다. 개수 제한은 없습니다.
- **메뉴 막대 묶음**(PLO-116): 띄운 패널이 하나 이상이면 `Open Library` 다음에 구분선, 제목 `띄워 둔 드롭`(`floatingDrops`), Drop 제목 목록(띄운
  순서), 구분선, `모두 숨기기`(`hideAllFloating`)와 `모두 닫기`(`closeAllFloating`)를 둡니다. 숨긴 패널이 하나라도 있으면 `모두 숨기기` 자리가
  `모두 보이기`(`showAllFloating`)입니다(모두 숨긴 뒤 목록에서 하나만 다시 보인 경우도 포함). 목록 항목은 띄운 Drop의 현재 제목이고, 고르면 그 패널만 보이고 앞으로 옵니다(앱은 활성화하지 않음). 띄운 패널이 없으면 묶음
  전체(구분선 포함)를 넣지 않습니다.
- **접근성**: 패널 창 제목이 Drop 제목이고 VoiceOver는 `띄운 드롭`(`floatingPanel`) 패널로 읽습니다. 제목 막대 버튼에 이름과 툴팁이 있습니다.

### 2.9 앱 안 업데이트 (PLO-118)

Sparkle 2로 업데이트를 확인하고 설치합니다. 결정과 배포 절차는 [update-method.md](../update-method.md)와
[release.md](../release.md), 보내는 정보는 [privacy.md](../privacy.md#update-checks)에 있습니다.

- 피드는 `https://plopcut.com/appcast.xml`, 업데이트는 EdDSA 서명(`SUPublicEDKey`)과 같은 팀의 Developer ID 서명이 맞아야
  설치합니다. 시스템 프로필은 보내지 않습니다(`SUEnableSystemProfiling` 끔).
- 피드와 공개 키가 둘 다 `Info.plist`에 있을 때만 업데이터를 시작합니다. 없으면 업데이트 항목을 모두 숨깁니다.
- 자동 확인은 기본으로 켜져 있습니다(`SUEnableAutomaticChecks`, 소유자 결정 2026-10-28). 두 번째 실행 때 묻지 않고 하루 한 번 정도
  확인하며, Settings 스위치로 끕니다. 이 선택과 마지막
  확인 시각은 Sparkle이 앱의 사용자 기본값에 저장하며 `settings.json`에는 쓰지 않습니다.
- `Check for Updates`(`checkForUpdates`)는 앱 메뉴(About 아래), 메뉴 막대 메뉴, Settings 정보 섹션에 있고 Sparkle의 창을 엽니다.
  확인이 진행 중이면 비활성입니다.
- 업데이트 창, 다운로드, 설치, 재실행은 Sparkle의 표준 화면과 동작을 그대로 씁니다.

## 3. 캡처

### 3.1 선택 텍스트 캡처

트리거는 전역 단축키(기본 `Shift+Cmd+C`) 하나이며 확인 방식(3.3)을 적용하고 별도 Save Popup 창을 엽니다. 도구 막대의
`선택한 텍스트 캡처` 버튼은 두지 않습니다. 최전면 앱이 Plopcut 자신이라 다른 앱의 선택을 가져올 수 없기 때문입니다(체크리스트 D-05).

캡처는 두 경로를 이 순서로 시도합니다. 단계 번호의 순서는 바꾸면 안 됩니다.

1. **출처 수집을 먼저** 합니다(3.4). 이 시점의 최전면 앱이 원본이기 때문입니다.
2. **접근성 읽기(1순위, 클립보드를 건드리지 않음)**: 최전면 앱의 프로세스로 만든 접근성 요소(`AXUIElementCreateApplication`)에서
   포커스된 요소의 선택 텍스트(`AXSelectedText`)를 읽습니다. 시스템 전역 요소(`AXUIElementCreateSystemWide`)는 Chrome에서
   실패하므로 쓰지 않습니다. 짧은 타임아웃을 걸고, 최전면 앱이 Plopcut이면 건너뜁니다. 비어 있지 않은 값이 나오면 7단계로
   갑니다(클립보드 백업·복원 없음). 읽기에 실패하거나 값이 비면 폴백으로 넘어가며 이것만으로 `no_selected_text`로 보지 않습니다.
   앱별 결과는 [ax-probe.md](ax-probe.md)에 있습니다.
3. **클립보드 폴백**: 클립보드를 백업합니다(텍스트와 PNG 이미지). 실패하면 경고 `clipboard_backup_failed`를 남기고 빈 스냅샷으로 계속합니다.
4. `Cmd+C`를 시뮬레이션합니다.
5. 클립보드 변경 횟수(change count)가 백업 시점과 달라질 때까지 25 ms 간격으로 최대 700 ms 기다립니다. 변경 횟수가
   달라졌을 때 문자열을 읽습니다. 변경 횟수를 얻지 못한 경우에만 텍스트 값 비교로 대체합니다.
6. **결과와 무관하게** 이전 클립보드를 복원합니다(3~5단계를 거친 경우만). 복원에 실패하면 경고 `clipboard_restore_failed`를
   추가하고 캡처는 성공으로 처리합니다. 백업이 불완전했다면 복원을 시도하되 마지막에 실패로 보고합니다.
7. 텍스트의 끝 `\r`/`\n`을 제거하고 공백뿐이면 비어 있는 것으로 봅니다. 비면 `no_selected_text`.
   복사된 텍스트가 이전 클립보드와 같더라도(변경 횟수만 달라졌다면) 유효합니다.
8. 제목을 추론하고(1.4) Draft(`type: text`, 노트 없음, 태그 없음, 경고 목록)를 만듭니다.

복사 시뮬레이션이나 대기 중 자동화 오류(`automation_unavailable`, `automation_failed`)는 `permission_missing`으로 바꾸고
`손쉬운 사용 권한을 System Settings에서 허용하라`는 안내를 덧붙입니다.

### 3.2 클립보드 캡처

트리거: 메뉴 막대의 `Save Clipboard`. (PRD에 있는 `Shift+Cmd+V`는 구현된 적이 없습니다. 체크리스트 D-01.)

1. 변경 횟수를 읽고 클립보드의 문자열과 이미지(PNG 우선, 없으면 TIFF를 PNG로 변환)를 한 번에 읽습니다.
2. 읽는 동안 변경 횟수가 바뀌었으면 `clipboard_changed`로 실패합니다.
3. 이미지가 있는데 디코딩에 실패하면 경고 `clipboard_image_unavailable`을 남기고 텍스트만으로 진행합니다. 텍스트도 없으면
   그 오류로 실패합니다.
4. 분류: 텍스트만 → `text`, 이미지만 → `image`, 둘 다 → `mixed`, 둘 다 없으면 `clipboard_empty`.
5. 출처를 수집합니다. 최전면 앱이 Plopcut 자신이면(메뉴 막대에서 실행) 출처를 비우고 제목을 다시 추론합니다.

### 3.3 확인 방식

전역 단축키와 메뉴 막대 `Save Clipboard`에 적용하는 설정 `captureConfirmationMode`:

- `modal`: 항상 Save Popup을 엽니다.
- `instant`: **텍스트 Draft만** 노트와 태그 없이 즉시 저장하고 메뉴 막대에 성공 표시(2.1)를 보여 준 뒤 Library 새로고침 신호를 보냅니다.
  이미지와 `mixed` Draft는 `instant`에서도 팝업을 엽니다.

저장 실패는 다음처럼 처리합니다. 캡처와 즉시 저장의 실패는 오류를 보관하고 메뉴 막대에 실패 표시(2.1)만 하며 메인 창을 열거나
포커스하지 않습니다(PLO-96). 예외는 선택 텍스트 캡처의 손쉬운 사용 권한 없음(`permission_missing`)입니다. 이때는 macOS 권한 요청(실행마다 한 번)을
띄우고 메인 창을 열어 이유와 `시스템 설정 열기`를 보여 줍니다. 보관한 오류는 메인 창이 열렸을 때 **한 번만** 꺼내어
`{pendingFailed}: {메시지}` 상태 메시지로 보여 줍니다. 메뉴 막대의 오류 항목은 이 보관과 별개로, 메뉴를 열 때 같은 사유를 보여 줍니다.

### 3.4 출처 수집 (최선 노력)

실패해도 저장을 막지 않고 경고만 남깁니다.

- 최전면 앱 이름과 앞 윈도우 제목(제목을 못 얻으면 빈 값).
- 최전면 앱이 `Google Chrome`이면 앞 창의 활성 탭 URL. 실패 시 경고 `chrome_url_failed`. 앱·윈도우 수집 실패는
  `metadata_failed`.
- 파일 경로는 신뢰할 수 있는 API가 있을 때만. 레거시는 수집하지 않습니다.

### 3.5 Save Popup

- 내용: 유형 표시(저장 대상, 제목 앞에 16 pt 컬러 마크), 제목 입력란(아래), 텍스트 또는 이미지 미리보기(텍스트는 2.6의 자동 감지 형식으로 같은 방식으로
  렌더링하고, 미리보기 오른쪽 위에 형식 이름 배지를 둡니다. 팝업에서는 형식을 바꾸지 않습니다. PLO-101), 출처 요약(앞에 출처 앱 아이콘,
  `앱 · 윈도우 · URL`, 없으면 `알 수 없는 출처`이고 아이콘 없음), 경고, 노트 입력(선택), 태그 입력, 최근 태그 칩(누르면 입력에 추가,
  이미 있으면 무시), 저장 버튼, 취소 버튼, 닫기. 태그 칩과 최근 태그는 `#design`처럼 `#`을 붙여 표시합니다. 하단 버튼 줄 왼쪽에
  단축키 힌트 `popupShortcutHint`(`⌘↩ 저장 · esc 취소`)를 보조 회색 작은 글씨로 둡니다(PLO-89).
- 태그가 없을 때도 태그 입력 아래에 칩 한 줄 높이의 빈 자리를 둡니다. 첫 태그를 등록해도 아래 내용과 창 높이가 움직이지
  않습니다(PLO-100 수정).
- `mixed` Draft: 텍스트/이미지 중 **하나를 고르게** 합니다. 고른 유형 하나만 Drop으로 저장합니다.
- 제목 입력란(PLO-105): 유형 표시 바로 아래 맨 위에 `제목`(`titleField`) 라벨과 한 줄 입력란을 두고, 저장할 유형의 자동 제목을
  미리 채웁니다. 자동 제목은 1.4의 순서(윈도우 제목 → 앱 이름 → 본문 첫 줄 → 기본 제목, 이미지는 `Image Drop`)로 정합니다.
  - 사용자가 고치기 전에는 입력값이 자동 제목을 따라갑니다. `mixed` Draft에서 유형을 바꾸면 그 유형의 자동 제목으로 바뀝니다.
    고친 뒤에는 유형을 바꿔도 입력값을 그대로 둡니다. 입력값을 자동 제목과 같게 되돌리면 다시 따라갑니다.
  - 입력란 오른쪽 안쪽의 `자동`(`autoTitle`, 툴팁 `autoTitleHelp`) 버튼은 입력값이 자동 제목과 다를 때만 누를 수 있고, 누르면 자동
    제목으로 되돌립니다.
  - 입력란 아래 보조 문구는 자동 제목을 어디서 가져왔는지와 비우면 자동 제목으로 저장한다는 점을 알립니다: 윈도우 제목
    `titleHintWindow`, 앱 이름 `titleHintApp`, 본문 첫 줄 `titleHintFirstLine`, 가져올 값이 없음 `titleHintDefault`.
  - 저장할 때 입력값의 앞뒤 공백을 지웁니다. 비면 명시한 제목 없이 저장해 저장소가 자동 제목을 씁니다. 그 밖에는 그 값을 명시한
    제목으로 저장합니다(최대 80자, 1.4). 입력란을 건드리지 않고 저장하면 PLO-105 이전과 같은 제목입니다.
  - 팝업이 열릴 때 포커스는 지금처럼 노트에 있습니다. 제목 입력란은 클릭해서 고칩니다. 제목 입력란에 포커스가
    있어도 `Cmd+Enter`는 저장, Escape는 취소입니다.
- PLO-105에서 넣은 `저장 후 고정` 체크박스는 PLO-100 수정(2026-10-19)에서 뺐습니다. 고정은 저장한 뒤 Library에서 합니다.
- `Cmd+Enter`는 저장(저장 중이면 무시), Escape와 닫기 버튼은 취소. 열릴 때 팝업에 포커스합니다. 팝업은 앱을 활성화하지 않는 패널이라 메인 창을 앞으로 가져오지 않고, 저장·취소 뒤에는 사용자가 쓰던 앱에 포커스가 남습니다(PLO-96).
- 별도 창 팝업: Draft를 받기 전에는 `preparing` 문구를 보여 줍니다. 저장 성공 시 메뉴 막대 성공 피드백(2.1)을 보이고(PLO-98) 최근 태그를 갱신하고 Library 새로고침 신호를
  보낸 뒤 창을 닫습니다. Library는 새로고침 후 저장된 새 Drop을 선택합니다(체크리스트 L-10). 취소해도 창을 닫고 Draft를
  버립니다.
- 저장 실패: 팝업을 닫지 않고 오류를 표시합니다.
- 별도 창 팝업이 이미 열려 있을 때 단축키로 다시 캡처하면 같은 창을 재사용하고 새 Draft가 이전 Draft를 대체합니다
  (체크리스트 P-14).
- 별도 창 팝업의 크기와 위치는 2.1을 따르며, 팝업에도 앱의 테마 설정을 적용합니다.

## 4. 설정 화면

메인 창 안의 화면이며 사이드바는 Library와 같습니다. 내용: 저장 폴더(경로 표시, 폴더 선택 버튼, 선택을 취소하면 `folderCancelled`
안내), 테마(시스템/라이트/다크, 앱 외형에 즉시 적용하고 시스템으로 돌아가면 재정의 해제), 선택 텍스트 단축키(입력, 저장, 형식
안내, 저장 중 상태), 저장 확인 방식(팝업 표시/텍스트 즉시 저장), 권한 상태, 정보. 정보 섹션은 앱 아이콘([5.1](#51-브랜드-마크와-앱-아이콘)),
앱 이름 `Plopcut`, 버전(`aboutVersion`)을 한 줄에 표시하고 `Finder에서 로그 보기` 버튼을 둡니다(PLO-89). 업데이터가 있는 빌드면
그 위에 `자동으로 업데이트 확인` 스위치(`checkUpdatesAutomatically`, 설명 `checkUpdatesAutomaticallyHelp`)와 `업데이트 확인` 버튼을
둡니다([2.9](#29-앱-안-업데이트-plo-118)).

- 저장 폴더를 바꾸면 이후의 스캔과 저장이 새 폴더를 씁니다. 기존 Drop을 옮기거나 복사하지 않습니다.
- 첫 실행(`hasCompletedFirstRun == false`): 모달로 기본 폴더 사용 또는 폴더 선택을 요구하고, 둘 중 하나가 끝나면
  `hasCompletedFirstRun = true`로 저장합니다. 선택을 취소하면 모달이 남습니다.
- 단축키를 바꾸면 새 단축키를 먼저 등록하고 이전 것을 해제한 뒤 설정을 저장합니다. 등록 실패나 저장 실패면 이전 단축키를
  유지(롤백)하고 설정 파일은 바뀌지 않습니다. 형식이 잘못되면 저장하지 않고 `invalid_selected_text_shortcut`을 보여 줍니다.
- 권한 상태 세 항목: 손쉬운 사용(`AXIsProcessTrusted`), 클립보드(텍스트를 읽을 수 있는지), 자동화(항상 `알 수 없음`, Chrome
  URL을 처음 읽을 때 시스템이 묻는다는 안내). 각 항목은 상태(허용/없음/알 수 없음), 설명, 다음 행동을 가집니다.

### 5.1 브랜드 마크와 앱 아이콘

PLO-89(2026-10-15)에서 정한 "p." 모노그램입니다. 마크는 100 × 100 좌표계에서 그리고 세 도형 모두에 `translate(-5 -6)`을 적용합니다.
마크만 그릴 때는 `viewBox="10 10 80 80"`으로 자릅니다.

| 도형 | 정의 | 그리기 |
| --- | --- | --- |
| 줄기 | `M23 25H35V88H23Z` | 채움 |
| 볼 | 원 중심 (44, 46), 반지름 15 | 획 12, 채움 없음 |
| 점 | 원 중심 (80, 59.5), 반지름 7.5 | 채움 |

| 색 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 그래파이트 | `#26282C` | 앱 아이콘 배경, 밝은 바탕 위 컬러 마크의 p |
| 마크 블루 | `#4F8CFF` | 마크의 점(앱 아이콘, 앱 안 컬러 마크) |
| 흰색 | `#FFFFFF` | 앱 아이콘의 p, 어두운 바탕 위 컬러 마크의 p |

- **앱 아이콘**: 1024 × 1024 캔버스, 본체 `x=100 y=100` 824 × 824, 모서리 반경 185, 그래파이트 단색 배경(그라데이션·광택·흐림
  없음). 마크 좌표계를 `translate(262 262) scale(5)`로 옮기고 p는 흰색, 점은 마크 블루입니다.
- **컬러 마크**: 빈 Library(72 pt)와 Save Popup 제목 앞(16 pt). 접근성 이름 `appLogo`. p는 라이트 모드에서 그래파이트, 다크 모드에서
  흰색 `#FFFFFF`(앱 아이콘과 같은 색, PLO-90)이고 점은 두 모드 모두 마크 블루입니다.
- **메뉴 막대**: 같은 마크의 단색 템플릿 이미지(`NSImage.isTemplate`, 18 pt, @2x 36 px). 점도 같은 색이고 시스템이 색을 입힙니다.
  저장 피드백(2.1)은 점 자리에 다음 도형을 그린 이미지를 씁니다(마크 좌표, `translate(-5 -6)` 포함).

| 상태 | 점 자리의 도형 |
| --- | --- |
| 기본 | 점: 원 (80, 59.5) 반지름 7.5, 채움 |
| 저장 성공 | 체크: `M71 59L77.5 65.5L89 51`, 획 7, 둥근 끝·둥근 이음 |
| 저장 실패 | 느낌표: 선 `M80 42V56` 획 7 둥근 끝 + 원 (80, 65) 반지름 3.8 채움 |

종료하지 않습니다.

## 7. Markdown 내보내기

`Markdown 내보내기`는 저장 대화상자(기본 파일명 `{slug(제목)}.md`, 필터 `md`)를 열고, 취소하면 아무것도 쓰지 않습니다.
내용은 다음 순서이며 값이 없는 줄과 섹션은 생략합니다.

```markdown
# {title}

## Metadata

- Type: {type}
- Created: {createdAt}
- Updated: {updatedAt}
- Tags: {tag, tag}
- App: {appName}
- Window: {windowTitle}
- URL: {url}
- File: {filePath}

## Text

{text}

## Note

{note}
```

Metadata의 `Type`, `Created`, `Updated`는 항상 있고, 나머지 항목과 `Text`·`Note` 섹션은 값이 있을 때만 출력합니다. 본문과
노트는 앞뒤 공백을 지우고 끝에 줄바꿈 하나를 붙입니다. 이미지 Drop에는 `Text`가 없습니다.

## 8. Swift 구현 제안 (구속력 없음)

| 영역 | 후보 |
| --- | --- |
| 3열 + 인스펙터 | `NavigationSplitView`와 `.inspector`. 좁은 폭의 오버레이 동작은 직접 확인. |
| 도구 막대와 검색 | SwiftUI `.toolbar`, `.searchable`. 아이콘 축약과 Escape 규칙은 직접 확인. |
| 클립보드 | `NSPasteboard`와 `changeCount`를 앱 안에서 직접 사용. 별도 `swift -e` 프로세스가 필요 없습니다. |
| 복사 시뮬레이션 | `CGEvent`(손쉬운 사용 권한 필요). |
| 출처 | `NSWorkspace.frontmostApplication`, 접근성 API로 윈도우 제목, Chrome URL은 `NSAppleScript`(`NSAppleEventsUsageDescription` 필요). |
| 전역 단축키 | Carbon `RegisterEventHotKey` 또는 검증된 라이브러리. 저장된 `Shift+Cmd+C` 문자열을 해석. |
| 휴지통 | `FileManager.trashItem`. |
| 메뉴 막대 | `NSStatusItem`. |
| 저장소 | `Codable`과 `FileManager`. 모델과 저장은 UI와 분리해 순수 단위 테스트가 가능하게. |

### 권장 구현 순서

1. 저장 계층(모델, 읽기·쓰기, 태그, ID, 설정)과 [픽스처](fixtures/README.md) 기반 호환 테스트.
2. Library 읽기 전용 화면(사이드바, 목록, 본문, 인스펙터, 도구 막대)과 서체관리자 대조.
3. 편집(제목, 노트, 태그, 자동 저장), 삭제, 내보내기.
4. 캡처(선택 텍스트, 클립보드), Save Popup, 출처 수집, 권한.
5. 설정, 단축키 변경, 메뉴 막대, 첫 실행.
6. [체크리스트](behavior-checklist.md) 전 항목 확인.
