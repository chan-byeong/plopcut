# plopcut 디자인 시스템

이 문서는 plopcut의 레이아웃 값, 시각 토큰, 컴포넌트 동작과 상태, 접근성, 검증 기준을 정의합니다. 확정 시안과 영역별 구현
기준은 [`Design.md`](../Design.md)를 참고합니다.

plopcut은 SwiftUI와 AppKit의 기본 컨트롤, 시스템 색, 시스템 텍스트 스타일, 시스템 재질을 씁니다. 그래서 이 문서가 직접
정하는 값은 레이아웃 수치와 브랜드 색(앱 강조색, 선택 행 채움, 마크 색)뿐이고, 색·서체·모양 토큰은 "의미 → 시스템 구현" 대응으로
적습니다. 브랜드 색은 PLO-89에서 정했고, 코드에 hex로 쓰지 않고 에셋 카탈로그의 이름 있는 색으로 둡니다. 수치의 단위는 모두 pt(논리
포인트)입니다. 수치는 plopcut의 구현 기준이며 Apple 공식 디자인 토큰이나 참고 이미지에서 측정한 값이 아닙니다. 새 UI를 만들 때
시스템 값으로 표현할 수 있으면 직접 색이나 크기를 정하지 않습니다.

## 간격

간격은 코드의 `Spacing`(`PlopcutApp/Sources/Plopcut/DesignSystem/Spacing.swift`) 일곱 단계만 씁니다. 값은 보기 좋은 숫자를 고르는 것이
아니라 **역할**로 고릅니다. 같은 역할이면 어느 화면에서든 같은 값입니다. 관계가 가까울수록 작은 값을 써서, 간격만으로 무엇이
무엇에 딸렸는지 읽히게 합니다.

| 토큰 | 값 | 역할 | 예 |
| --- | ---: | --- | --- |
| `Spacing.xxs` | 2 pt | 한 항목의 여러 줄, 레이블과 값 | 목록 행의 제목·미리보기·메타 줄, 출처 상세의 레이블·값, 경고 목록, 섹션 꼬리말 |
| `Spacing.xs` | 4 pt | 제목과 그 컨트롤, 요소에 딸린 설명, 입력 면 세로 안쪽 | 노트 제목·입력, 유형 머리글·Drop 제목, 팝업 미리보기·출처, 목록 행 세로 여백 |
| `Spacing.s` | 8 pt | 한 그룹 안의 형제 요소, 입력 면 가로 안쪽 | 버튼·칩·인라인 항목 사이, 태그 섹션의 줄, 출처 상세 항목 사이, 행 아이콘·텍스트 |
| `Spacing.m` | 12 pt | 작은 표면의 섹션 사이 | Save Popup 필드 묶음, 첫 실행 시트 |
| `Spacing.l` | 16 pt | 패널의 섹션 사이, 패널·팝오버·팝업 안쪽 여백 | 본문·인스펙터 섹션 사이, 인스펙터·필터 팝오버·팝업 여백, 목록 칩 줄 좌우 |
| `Spacing.xl` | 20 pt | 시트 안쪽 여백(macOS 표준 여백) | 첫 실행 시트 |
| `Spacing.xxl` | 24 pt | 읽기 영역 안쪽 여백 | Drop 본문 |

- 섹션 사이 간격은 그 안의 간격보다 한 단계 이상 커야 합니다. 예를 들어 인스펙터는 섹션 안이 `xs`·`s`, 섹션 사이가 `l`입니다.
- 패널(본문, 인스펙터)은 섹션 사이에 `l`, 작은 표면(팝업, 시트)은 `m`을 씁니다. 같은 역할을 표면 크기에 맞춰 한 단계 줄인 것입니다.
- 제목에 딸린 머리글(유형 레이블)은 제목과 한 묶음으로 두고 `xs`를 씁니다.
- 직접 그린 입력 면의 안쪽 여백은 가로 `s`, 세로 `xs`입니다. 제목처럼 편집할 때만 테두리가 보이는 필드는 테두리를 바깥으로
  넓혀 글자 위치가 움직이지 않게 합니다.
- 예외는 시각 정렬용 보정값뿐이며 코드에 이유를 주석으로 적습니다: 목록 행 아이콘을 1 pt 내려 제목과 맞추기, 노트 자리 표시
  글자를 `NSTextView`의 줄 안쪽 여백(5 pt)만큼 밀기. 스택이 간격을 직접 관리할 때의 `spacing: 0`도 허용합니다.
- 목록 행 높이, 사이드바 인셋, Form 행 간격 같은 시스템 컨트롤 내부 간격은 바꾸지 않습니다.

## 레이아웃

검색 축약과 패널 배치는 모두 창 콘텐츠 영역의 실제 너비(`GeometryReader`)로 계산합니다. 참고 이미지는 패널 관계를 보여 주고,
다음 토큰은 구현 크기를 정의합니다.

코드에서는 `LayoutMetrics`(`DesignSystem/LayoutMetrics.swift`)의 이름으로 씁니다. 사이드바·목록의 기본 너비와 범위는
`settings.json`과 같은 원본인 `PlopcutCore`의 `PaneWidths`에서 가져옵니다.

| 코드 이름 | 값 | 용도 |
| --- | ---: | --- |
| `sidebarDefault`, `sidebarRange` | 220 pt (180–320) | 펼친 사이드바 기본 너비와 끌어서 조절할 수 있는 범위 |
| `listRange` (기본은 `PaneWidths.default.library`) | 330 pt (300–560) | Drop 목록 기본 너비와 조절 범위. 최소 300 |
| `inspectorWidth` | 280 pt | 정보 인스펙터 너비(고정, 옆 배치와 오버레이 공통) |
| `bodyMin` | 360 pt | 본문 최소 너비 |
| `dividerAllowance` | 8 pt | 인스펙터 배치 계산에 넣는 패널 구분선 하나의 몫 |
| `windowMin`, `windowDefault` | 960 × 640, 1120 × 720 pt | 메인 창 최소·기본 크기 |
| `sideBySideWidth` | 1176 pt | 인스펙터를 본문 옆에 두는 최소 콘텐츠 너비. 위 값들의 합으로 계산 |
| `compactSearchWidth` | 1050 pt | 이 너비 미만에서 검색을 아이콘으로 축약 |
| `popoverWidth` | 280 pt | 작은 폼을 담는 팝오버(필터) |

배치 판단은 숫자를 직접 비교하지 않고 `LayoutMetrics.inspectorFitsBeside(contentWidth:sidebarHidden:)`,
`LayoutMetrics.searchIsCompact(windowWidth:)`를 씁니다.

사이드바와 목록의 기본 너비는 `settings.json`의 `paneWidths`에서 읽습니다. 사이드바 인셋, 행 높이, 구분선 모양은
`NavigationSplitView`와 `NSSplitView`가 그립니다.

### 반응형 레이아웃 및 패널 상태

Library는 서체관리자.app에서 관찰한 인라인 사이드바와 축약 검색 동작을 따릅니다.
창의 최소 너비는 960 pt이며, 사이드바를 너비 구간만으로 접지 않습니다.

- 앱 실행 시 사이드바를 펼칩니다. 사용자의 접힘 선택을 창 크기 변경과
  Library/Settings 왕복 중 유지합니다. Settings에서도 같은 사이드바를
  표시하고, Library로 돌아오면 이전 선택을 복원합니다.
- 사이드바를 접으면 목록과 본문이 빈 공간을 사용합니다. 펼친 사이드바는
  항상 본문 옆에 배치하며 오버레이로 표시하지 않습니다.
- 콘텐츠 너비에 사이드바 220, 목록 최소 300, 본문 최소 360, 구분선 두 개
  각 8, 인스펙터 280이 들어가면(1176 pt, 사이드바를 접으면 956 pt) 인스펙터를
  옆에 둡니다.
- 공간이 부족하면 인스펙터를 접습니다. 토글로 우측 오버레이를 열고 같은
  토글이나 Escape로 닫으며, 닫으면 Drop 목록으로 포커스를 돌립니다(체크리스트
  D-13: 도구 막대 버튼은 '전체 키보드 접근'이 꺼져 있으면 포커스를 받지 않음).
  펼침을 선택한 인스펙터는 공간이 확보되면 다시 본문 옆에 표시합니다.
  사용자가 옆에 있는 인스펙터를 직접 접으면 그 선택을 유지합니다.
- 창 크기 변화로 저장된 사용자 너비를 덮어쓰지 않습니다. 구분선을 마우스로
  끌었을 때만 `paneWidths`를 저장합니다. 구분선은 키보드로 조절하지 않으며
  접근성 값은 AppKit 기본으로 제공합니다(체크리스트 D-14, L-15).
- 1050 pt 미만에서 상단 검색은 아이콘입니다. 클릭 또는 `Cmd+F`로 검색
  입력을 열고 포커스합니다. Escape는 입력을 닫지만 검색어와 결과를
  유지합니다. 지우기 버튼은 검색어를 비우고 전체 결과를 다시 표시합니다.

패널을 접거나 창 크기를 바꿔도 선택한 Drop, 검색어, 필터, 노트·태그의
편집 초안을 유지합니다. 접힌 패널 컨트롤은 Tab 순서에서 제외합니다.
패널 상태는 실행 중 표시 상태이며 새 영구 설정이나 Drop 저장 형식을
추가하지 않습니다.

## 색상 및 재질 토큰

Settings의 테마 선택(시스템·라이트·다크)은 `NSApp.appearance`로 모든 창에 적용합니다. 시스템을 고르면 재정의를 해제해 macOS의
라이트·다크 설정을 따릅니다. 아래 색은 라이트·다크에 맞춰 시스템이 바꿉니다. 예외는 브랜드 색(`color-accent`, `color-selection`,
`color-brand-mark`)입니다. 강조색의 테마별 값은 `PlopcutApp/Resources/Assets.xcassets`의 `AccentColor`가 가지며,
`scripts/make-app.sh`가 `actool`로 컴파일하고 `Info.plist`의 `NSAccentColorName`으로 연결합니다(`swift run`처럼 번들 밖에서
실행하면 시스템 강조색이 쓰입니다).

선택 행은 직접 칠하지 않고 `List`의 기본 선택을 씁니다(PLO-91). macOS는 선택 채움을 앱 강조색에서 만들기 때문에 `#2F6BFF`와 같은 값은
아닙니다. PLO-91에서 다크 모드 활성 창의 사이드바 선택 채움을 측정하니 약 `#3268D0`이었고 흰 글자와의 대비는 약 5.2:1입니다. 참고로
`#2F6BFF` 위 흰 글자는 4.499:1로 4.5:1에 조금 못 미칩니다. 사용자가 시스템 강조색을 '여러 색상' 외의 색으로 고르면 macOS는 앱 강조색
대신 그 색으로 표준 컨트롤과 선택 행을 그립니다(Apple 문서 기준, 기기에서 확인하지 않았습니다). 이것은 의도한 동작으로 둡니다.

| 의미 토큰 | SwiftUI·AppKit 구현 | 용도 |
| --- | --- | --- |
| `color-canvas` | 창 기본 바탕(시스템) | 상단과 본문이 공유하는 불투명 바탕 |
| `color-surface` | `NSColor.textBackgroundColor` | 편집 중인 제목, 노트 입력, 단축키 필드의 바탕 |
| `color-surface-muted` | `.quaternary` 40% | 팝업 미리보기 같은 보조 면 |
| `color-sidebar-material` | `.listStyle(.sidebar)`의 시스템 재질 | 사이드바 |
| `color-control-material` | 통합 도구 막대의 시스템 재질 | 도구 막대 컨트롤 |
| `color-overlay-material` | `.regularMaterial` | 인스펙터 오버레이, 알림 배너 |
| `color-text-primary` | `.primary` | 제목과 주요 본문 |
| `color-text-secondary` | `.secondary` | 보조 내용, 레이블, 시각, 메타데이터, 안내 |
| `color-border` | `Divider()`, `.separator` | 패널 사이와 앱 아이콘의 절제된 구분선 |
| `color-control-boundary` | `.secondary` 30%, 1 pt | 직접 그린 입력 필드의 기본 외곽선 |
| `color-accent` | `Color.accentColor`(`AccentColor` 에셋: 라이트 `#2F6BFF`, 다크 `#4F8CFF`) | 링크, 포커스 외곽선, 기본 버튼, 라디오·토글 |
| `color-selection` | `List` 기본 선택. 활성 창은 앱 강조색에서 만든 색(다크 측정값 약 `#3268D0`), 비활성 창은 시스템 중성색 | 사이드바와 목록의 선택 행 채움. 선택 행의 글자·아이콘은 흰색 |
| `color-icon-secondary` | `.secondary` | 선택하지 않은 사이드바 행 아이콘, 목록 행의 태그(`#design`) |
| `color-brand-mark` | 그래파이트 `#26282C`, 마크 블루 `#4F8CFF` | 앱 아이콘과 컬러 마크([구현 명세 5.1](swift-migration/spec.md#51-브랜드-마크와-앱-아이콘)) |
| `color-danger` | `.red`, `role: .destructive` | 삭제 동작, 오류 텍스트, 권한 없음 |
| `color-warning` | `.orange` | 복구 가능한 경고, 읽지 못한 Drop, 태그 중복 안내 |

본문 전체는 도구 막대와 같은 불투명 바탕을 사용합니다. 별도 도구 막대 배경 띠나 아래 선은 두지 않습니다. 재질은 사이드바, 도구
막대, 인스펙터 오버레이, 알림 배너에만 쓰고, 옆에 놓인 인스펙터는 본문 바탕에 `Divider()` 경계만 둡니다. 텍스트가 많은 면에는
투명도가 높은 재질을 쓰지 않습니다. 저장 성공은 색이 아니라 `저장됨` 문구로 알립니다.

시스템 재질과 색은 '투명도 줄이기'에서 불투명해지고 '대비 증가'에서 경계가 강해집니다. 그래서 이 설정을 직접 처리하지
않습니다. 직접 색을 정해야 하면 이 설정에서도 읽을 수 있는지 확인합니다. 재질을 탐색·제어 영역과 콘텐츠 영역에 구분해 쓰는
근거는 [Apple 재질 지침](https://developer.apple.com/design/human-interface-guidelines/materials)을 참고합니다.

## 타이포그래피

시스템 글꼴과 SwiftUI 텍스트 스타일을 사용하고 한글 대체 글꼴 선택은 운영체제에 맡깁니다. 크기를 pt로 고정하지 않으므로
시스템 텍스트 크기 설정을 따릅니다. 단축키 표기에는 시스템 고정폭 글꼴(`.system(.body, design: .monospaced)`)을 사용합니다.

| 토큰 | 텍스트 스타일 | 용도 |
| --- | --- | --- |
| `type-caption` | `.caption` | 시각, 메타데이터, 저장 상태, 칩, 경고, 필드 안내 |
| `type-label` | `.callout.weight(.semibold)` | 팝업 필드 레이블 |
| `type-body` | `.body` | 컨트롤, Drop 본문, 노트 |
| `type-preview` | `.callout` | 목록 행 미리보기, 팝업 출처 |
| `type-row-title` | `.body`, `.semibold` | 목록 행 제목 |
| `type-section` | `.headline` | 인스펙터 섹션 제목, 팝업 제목 |
| `type-title` | `.title.bold()` | Drop 제목 |

선택, 오류, 저장 상태를 색상만으로 전달하지 말고 텍스트, 형태, 접근 가능한 이름이 있는 아이콘을 함께 사용합니다.

## 형태, 크기 및 아이콘

표준 컨트롤(버튼, 텍스트 필드, 피커, 목록 행, 도구 막대 버튼)의 모양과 크기는 시스템이 정합니다. 직접 정하는 값은 아래뿐입니다.
창 바깥 모서리와 사이드바 인셋 모양은 시스템이 담당합니다.

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `Radius.field` | 6 pt | 직접 그린 입력 면과 콘텐츠 우물: 제목, 노트, 팝업 노트·미리보기, 단축키 필드 |
| `Radius.appIcon` | 4 pt | 목록 행의 출처 앱 아이콘 |
| 입력 면 외곽선 | 1 pt `.secondary` 30%, 포커스 2 pt `Color.accentColor` | `inputSurface(focused:chrome:)` |
| 칩 | `.bordered` + `.small` | `chipStyle()`, 삭제 칩은 `RemovableChip` |
| 행 아이콘 자리 | 22 × 20 pt 상자 | 목록 행 선두 아이콘. 앱 아이콘(18 pt, 회색조)이 없으면 유형 심볼 |
| 컬러 마크 | 72 pt, 16 pt | 빈 Library, Save Popup 제목 앞. 모양과 색은 [구현 명세 5.1](swift-migration/spec.md#51-브랜드-마크와-앱-아이콘) |

한 컴포넌트에서만 쓰는 크기(인스펙터 노트 최소 높이 96, 팝업 노트 높이 52, 팝업 기본 크기 430 × 489(PLO-100), 이미지 최대 너비 640,
단축키 필드 최소 너비 180, 첫 실행 시트 너비 420)는 그 타입 안에 이름 있는 상수로 두고 이유를 주석으로 적습니다.

아이콘은 SF Symbols를 쓰고 의미별 기호는 [구현 명세 5장](swift-migration/spec.md)을 따릅니다. 아이콘만 있는 버튼에는 현지화된
`Label` 문구(접근성 이름)와 `.help` 툴팁을 제공합니다. 출처 앱 아이콘이 있으면 표시하고, 없으면 Drop 유형 심볼을 표시합니다.
태그는 `number`(#) 기호를 쓰고 어디서나 `#design`처럼 앞에 `#`을 붙여 표시합니다(저장 값에는 넣지 않음). 브랜드 마크와 메뉴 막대
아이콘은 SF Symbol이 아니라 [구현 명세 5.1](swift-migration/spec.md#51-브랜드-마크와-앱-아이콘)의 도형입니다.

## 포커스, 모션 및 접근성

표준 컨트롤의 키보드 포커스 링은 시스템이 그립니다. 시스템 링이 없는 직접 그린 입력 면(제목, 노트, 단축키 필드)은 포커스 중
2 pt 강조색 외곽선을 그리고, 레이아웃을 밀지 않습니다. 파란 선택 행의 포커스와 비포커스 선택 약화는 `List`가 처리합니다.
비활성 컨트롤은 `.disabled`로 네이티브 비활성 동작을 사용하며 투명도만으로 비활성 상태를 나타내지 않습니다.

WCAG AA 대비를 목표로 합니다. 일반 텍스트는 최소 4.5:1, 큰 텍스트(일반 18 pt 이상 또는 굵은 14 pt 이상)는 최소 3:1,
의미 있는 컨트롤 경계와 아이콘은 최소 3:1입니다. 시스템 색은 이 기준을 맞추도록 설계되어 있으므로, 직접 색이나 투명도를
조정한 곳(예: 입력 외곽선 `.secondary` 30%, 회색조 앱 아이콘)을 각 테마와 '대비 증가'에서 확인합니다.

| 모션 | 구현 | 용도 |
| --- | --- | --- |
| 인스펙터 오버레이 | `.move(edge: .trailing)` 전환, `.default` 애니메이션 | 좁은 창의 인스펙터 열기·닫기 |
| 알림 배너 | `.opacity` 전환, 3초 뒤 사라짐 | "휴지통으로 이동함" 같은 짧은 확인 |
| 메뉴 막대 저장 성공 | 점이 위에서 떨어져 앉음(200 ms, ease-out) → 체크 → 시작부터 약 1.1초 뒤 점 | 메인 창 없이 실행된 캡처의 성공 |
| 메뉴 막대 저장 실패 | 좌우 흔들림(240 ms) → 느낌표가 메뉴를 열 때까지 남음 | 메인 창 없이 실행된 캡처의 실패 |
| 그 밖의 전환 | 시스템 기본 | 사이드바 접기, 팝오버, 시트, 확인 대화상자 |

탄성 효과를 직접 만들지 않습니다. 메뉴 막대 저장 피드백은 브랜드 마크의 점을 쓰는 예외적인 직접 모션이며 위 표의 시간을 넘기지
않습니다. '동작 줄이기'가 켜지면(`accessibilityReduceMotion`, 메뉴 막대는 `NSWorkspace.accessibilityDisplayShouldReduceMotion`)
인스펙터 오버레이는 슬라이드하지 않고 최종 상태를 바로 표시하고(`InspectorOverlayMotion`), 메뉴 막대는 떨어짐과 흔들림 없이 기호만
바꿉니다. 새로 직접 만드는 이동 전환도 같은 방식으로 이 설정을 따릅니다. 모션이나
투명도만으로 전달하는 정보는 두지 않습니다. 자세한 기준은 Apple의
[모션 지침](https://developer.apple.com/design/human-interface-guidelines/motion)과
[접근성 설정 테스트 지침](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app)을 참고합니다.

## 새 요소의 배치와 피드백

새 기능을 넣을 때 동작과 피드백의 위치를 아래 표로 정합니다. 표에 맞는 자리가 없으면 새 자리를 만들기 전에 이슈에서 먼저
결정합니다.

### 동작 배치

| 동작의 범위 | 위치 | 구현 |
| --- | --- | --- |
| 현재 컬렉션을 좁히거나 패널을 여닫음(필터, 필터 지우기, 검색, 인스펙터 토글) | 도구 막대 | `.toolbar`의 `ToolbarItemGroup(placement: .primaryAction)`에 `ToolbarButton`. 순서를 한 곳에서 정하도록 모두 `MainWindow`의 `.toolbar`에 둡니다(PLO-92). 도구 막대에는 이 네 가지만 두며(PLO-89), 다른 동작은 메뉴 명령이나 사이드바로 보냅니다. |
| 선택한 Drop 하나에 적용(출처 열기, 내보내기, 휴지통) | 본문 동작 줄과 목록 우클릭 메뉴 양쪽 | 본문은 `DropDetailView`의 `actions` 줄에 `Label` 버튼. 우클릭 메뉴는 같은 동작을 같은 순서로, 파괴적 동작은 구분선 뒤 맨 끝에 둡니다. |
| 선택한 Drop의 속성 편집(노트, 태그 같은 저장 값) | 인스펙터 섹션 | `.headline` 제목 + 내용. 저장은 `DropEditor`의 자동 저장 경로를 씁니다. 별도 저장 버튼을 두지 않습니다. |
| 키보드 단축키가 필요한 동작, 자주 쓰지 않는 창 전체 동작(새로고침 `Cmd+R`) | 메뉴 명령 | `.commands`의 `CommandGroup`. 포커스에 따라 켜고 끌 때는 `TrashCommand`처럼 `FocusedValues`를 씁니다. 텍스트 편집 단축키와 겹치지 않게 합니다. |
| 앱 전체 설정 | Settings 섹션 | 아래 "Settings 항목 추가" 규칙. 화면 전환은 사이드바의 `설정` 행이며 도구 막대 버튼을 두지 않습니다. |
| 캡처할 때 입력하는 값 | Save Popup | 캡처 단계나 필드를 늘리는 변경은 이슈에서 먼저 결정합니다. |
| 메인 창이 닫혀 있어도 필요한 진입점 | 메뉴 막대 항목 | `MenuBar/MenuBarController.swift` |

파괴적 동작은 `role: .destructive`를 쓰고 실행 전에 `.confirmationDialog`로 확인합니다. 실행할 수 없는 동작은 숨기지 않고
`.disabled`로 둡니다. 예외적으로 의미가 없는 화면에서는 숨길 수 있습니다(예: Settings의 검색).

### 피드백

| 상황 | 표시 | 구현 |
| --- | --- | --- |
| 명령이 실패해 사용자가 알아야 함 | 경고 대화상자 | `LibraryModel.alertMessage`, 복구 동작이 있으면 `alertRecovery` 버튼 |
| 되돌릴 수 없는 동작의 확인 | 확인 시트 | `.confirmationDialog`, 파괴 버튼은 `role: .destructive` |
| 한 필드의 입력 오류 | 필드 바로 아래 문구 | `FeedbackText(kind: .fieldError)`: `.caption` + `.red` |
| 진행은 되지만 알아야 할 경고 | 관련 내용 옆 문구 | `FeedbackText(kind: .warning)`: `.caption` + `.orange` |
| 결과가 화면에 바로 보이지 않는 동작의 완료 | 알림 배너 | `LibraryModel.notice`(`NoticeBanner`, 3초) |
| 진행 중이거나 바뀐 저장 상태 | 해당 영역의 상태 문구 | `.caption` + `.secondary`(노트 저장 상태처럼) |
| 패널 전체가 비었거나, 로딩 중이거나, 읽기 실패 | 패널 자리 안내 | `ContentUnavailableView`, `ProgressView` |
| 폼이나 섹션 동작의 실패(Save Popup, Settings) | 폼 끝 문구 | `FeedbackText(kind: .error)`: `.callout` + `.red`. 팝업은 `AccessibilityNotification.Announcement`도 보냄 |
| 메인 창 없이 실행된 캡처의 결과 | 메뉴 막대 아이콘의 점 자리 기호 | `MenuBarFeedback`: 성공은 체크(약 1.1초), 실패는 느낌표(메뉴를 열 때까지)와 메뉴 맨 위의 오류 사유·`설정 열기`. 제목 문구는 쓰지 않고 접근성 이름이 상태를 알림([구현 명세 2.1](swift-migration/spec.md#21-창과-진입점)) |

새 피드백 방식을 만들지 않고 위 중 하나를 고릅니다. 성공은 색이 아니라 문구로 알리고, 결과가 화면에서 바로 보이면(예: 목록에 새
Drop이 나타남) 따로 알리지 않습니다.

## 공통 컴포넌트

공통 컴포넌트는 `PlopcutApp/Sources/Plopcut/DesignSystem/`에 있습니다. 새 UI는 아래 패턴을 직접 다시 만들지 않고 이
컴포넌트를 씁니다.

| 컴포넌트 | 쓰는 곳 | 담은 규칙 |
| --- | --- | --- |
| `Spacing` | 모든 간격 | 역할별 간격 7단계("간격") |
| `LayoutMetrics`, `Radius` | 창·패널 치수, 직접 그리는 반경 | 패널 너비와 배치 경계, 반경 |
| `inputSurface(focused:chrome:)` | 제목, 인스펙터 노트, 팝업 노트, 단축키 필드 | 필드 바탕, 1 pt 외곽선, 포커스 2 pt 강조색. `.whileFocused`는 편집할 때만 테두리를 보임 |
| `contentWell()` | 팝업 미리보기 | 읽기 전용 콘텐츠의 오목한 바탕 |
| `chipStyle()`, `RemovableChip` | 태그 칩, 필터 칩, 최근 태그 | 칩 모양, 삭제 칩의 `xmark`와 "제거 + 값" 접근성 이름 |
| `TagEntryField` | 인스펙터와 Save Popup의 태그 입력 | Return·쉼표·붙여넣기·추가 버튼 등록, 한글 조합 확정 키 무시, 중복 안내, 칩, 포커스 유지 |
| `FeedbackText` | 필드 오류, 경고, 폼 오류 | "피드백" 표의 크기·색·VoiceOver 특성 |
| `ToolbarButton` | 도구 막대 버튼 | SF Symbol + 같은 문구의 접근성 이름과 툴팁 |

### 분리 기준

다음 세 가지를 모두 만족하면 공통 컴포넌트로 분리합니다.

1. **반복**: 같은 모양이나 동작이 두 곳 이상에 있다.
2. **규칙을 담음**: 이 문서의 규칙(토큰, 피드백, 접근성)이나 틀리기 쉬운 동작(한글 조합, 포커스 복귀)을 담고 있어서,
   복사본끼리 어긋나면 일관성이나 동작이 깨진다.
3. **차이가 매개변수로 표현됨**: 사용처 사이의 차이를 매개변수 몇 개로 나타낼 수 있다. 구조가 다르면 억지로 합치지 않는다.

분리하지 않는 것: 시스템 컨트롤을 규칙 없이 감싸기만 하는 것, 한 화면에서만 쓰는 배치, 한 컴포넌트 고유의 크기(그 타입 안
이름 있는 상수로 둔다), 시스템이 스타일을 정하는 곳(Form 섹션 꼬리말의 저장 폴더 안내).

형태는 이렇게 고릅니다. 아무 컨트롤에나 입히는 모양은 수식어(`inputSurface`, `chipStyle`), 내용과 동작을 가진 것은
뷰(`TagEntryField`, `RemovableChip`)로 만듭니다. 여러 모델이 같은 컴포넌트를 쓰면 프로토콜로 연결합니다(`TagEditing`).
컴포넌트는 바깥 여백을 갖지 않고 안쪽 간격만 정합니다. 바깥 배치는 쓰는 쪽이 정합니다.

## 컴포넌트 동작과 상태

다음 표는 Library 컴포넌트의 기본·호버·포커스·선택·비활성·로딩·오류 처리를 정의합니다. 컴포넌트가 직접 소유하지 않는 상태는 해당
영역에서 안내합니다.

| 컴포넌트 | 기본·호버·포커스 | 선택·비활성·로딩 | 오류 및 접근성 |
| --- | --- | --- | --- |
| 도구 막대 (`MainWindow`의 `.toolbar`) | 시스템 도구 막대 버튼입니다. 호버·눌림·포커스는 시스템이 그립니다. 순서는 [필터 · 필터 지우기] [인스펙터 토글] [검색]입니다. macOS가 `.searchable` 검색 필드를 도구 막대 맨 오른쪽에 고정하므로(macOS 26의 `DefaultToolbarItem(kind: .search)`로도 옮겨지지 않음, PLO-92) 순서를 한 곳에서 정하려고 필터 버튼도 `MainWindow`에 둡니다. | 인스펙터 토글은 열림 상태에 따라 레이블을 `인스펙터 표시`·`인스펙터 숨기기`로 바꿉니다. 빈 Library에서는 필터와 인스펙터 토글을 비활성화합니다. Settings 도구 막대는 제목만 두고 필터·검색·인스펙터 토글을 숨기며 `Cmd+F`도 비활성화합니다. | 명령 오류는 경고 대화상자(`alert`)로 표시합니다. 모든 버튼에 현지화된 `Label` 문구와 `.help` 툴팁을 제공합니다. |
| 사이드바 행 (`SidebarView`) | `.sidebar` 목록의 `Label`과 `.badge` 개수로 유형·태그·Settings 행이 같은 구조를 씁니다. 아이콘은 `.secondary` 회색이고 태그 행은 `number`입니다. 섹션 제목은 시스템 소스 목록 제목입니다. 선택 행은 항상 하나입니다. | 활성 창에서는 `color-selection`(강조색 기반 시스템 선택) 채움과 흰 글자, 비활성 창에서는 중성색 선택이며 접근성 선택 상태도 함께 알립니다. 태그가 없으면 `태그 없음`을 표시합니다. 로딩은 목록 영역이 표시합니다. | 필터 오류는 목록 영역에 표시합니다. 선택 상태를 색상만으로 전달하지 않습니다. |

### Settings 항목 추가

Settings는 `SettingsView`의 `Form`(`.formStyle(.grouped)`)이며 섹션 순서는 저장 폴더, 일반, 캡처, 단축키, 권한, 정보입니다.

- **섹션**: 기능 하나에 `Section` 하나를 둡니다. 기존 섹션 주제에 맞으면 그 섹션에 넣고, 새 섹션은 성격이 가까운 섹션 옆에 두며
  정보 섹션은 항상 마지막입니다. 항목이 여러 줄이면 `Settings/` 아래 별도 뷰(`ShortcutSection`처럼)로 나눕니다.
- **컨트롤**: 선택지 3개 이하의 짧은 값은 `.pickerStyle(.segmented)`, 설명이 필요한 선택지는 `.radioGroup`, 켜기·끄기는
  `Toggle`, 읽기 전용 값은 `LabeledContent`를 씁니다.
- **즉시 적용이 기본**: 선택하는 순간 `settings.json`에 저장하고 적용합니다. 저장에 실패하면 이전 값으로 되돌리고 오류를
  표시합니다(`SettingsModel.setTheme` 참고).
- **저장·취소 버튼은 예외**: 값을 시스템에 등록해야 해서 실패할 수 있거나(전역 단축키), 여러 단계로 입력하는 값만 섹션 안
  오른쪽 아래에 `취소`·`저장`을 둡니다. 저장하지 않고 화면을 떠나면 변경을 버립니다.
- **문구**: 컨트롤 하나에 대한 짧은 안내는 `.caption` + `.secondary`, 상태를 설명하는 문단은 `.callout` + `.secondary`,
  오류는 섹션 끝에 `.red` 문구와 `.accessibilityAddTraits(.updatesFrequently)`로 둡니다.
- **시스템 설정이 필요한 항목**: 상태를 문구로 보여 주고, 해결할 수 있으면 `시스템 설정 열기` 버튼을 둡니다(`PermissionsSection`).
- **정보 섹션**: 앱 아이콘, 앱 이름 `plopcut`, 버전(`aboutVersion`)을 한 줄에 두고 `Finder에서 로그 보기` 버튼을 오른쪽에 둡니다.

### 노트 편집기

600 ms 디바운스와 포커스 이탈 저장을 유지합니다. 편집기가 대기 상태일 때 안내 문구 “자동 저장”을 계속 표시합니다. 편집 후에는
`변경됨`, 저장 중에는 `저장 중`, 성공 후에는 다음 편집 또는 선택 Drop 변경까지 `저장됨`을 표시합니다. 저장 중에도 입력
필드를 편집할 수 있습니다.

저장 실패 시 입력 텍스트를 유지하고 `저장 실패`와 `다시 시도` 동작을 표시합니다. 저장이 성공할 때까지 사용자의 텍스트를
지우거나 바꾸지 않습니다. 저장이 진행 중일 때 새 편집이 들어오면 일반 디바운스에 따라 최신 값을 저장합니다. 상태 문구는
노트 제목 옆에 하나의 접근성 요소로 묶어 표시합니다. 구현은 `DropEditor.swift`입니다.

### 태그 편집기

등록 전 초안과 등록된 칩을 분리합니다. Return, 쉼표, 추가 버튼은 같은 등록 동작을 호출하고, 쉼표가 든 텍스트를 붙여 넣어도
등록합니다. 한글 입력기 조합을 확정하기만 하는 Return·쉼표로는 등록하지 않습니다. 한글 2벌식은 AppKit 필드에서
`hasMarkedText`로 조합 여부를 알 수 없으므로 키 입력을 따라가는 `CompositionGuard`로 판정합니다(체크리스트 I-01).

등록 값은 `PlopcutCore`의 `Tags.parse`로 정규화합니다. 규칙은 앞뒤 공백 제거, 선행 `#` 모두 제거, 소문자화, 빈 태그 제외,
입력 순서를 유지한 중복 제거입니다. 빈 초안은 무시하고, 중복은 새 칩을 만들지 않은 채 “이미 추가됨”을 표시합니다. 등록에
성공하면 초안을 비우고 입력에 포커스를 유지합니다. 칩 삭제 뒤에도 입력으로 포커스를 돌립니다. 저장 실패 시 초안과 칩을 유지하고
노트 편집기와 같은 재시도 경로를 제공합니다.

## 키보드 및 패널 포커스

`Cmd+F`는 모든 창 너비에서 검색에 포커스하고, Drop 목록에서는 위·아래 화살표로 항목을 선택합니다. `Cmd+Backspace`는 선택한
Drop의 삭제 확인을 엽니다. 제목 편집은 Return으로 확정하고 Escape로 되돌리며, 둘 다 포커스를 목록으로 돌립니다. Tab 순서는
시스템 순서를 따르며 숨겨진 컨트롤은 포커스 순서에서 제외합니다.

패널 토글은 항상 접근할 수 있어야 합니다. 오버레이가 도구 막대나 자기 토글을 가리지 않게 합니다. Escape는 열린 오버레이를 닫고
Drop 목록으로 포커스를 돌립니다. 검색 편집 중에는 첫 Escape가 검색을 닫고, 다음 Escape가 오버레이를 닫습니다. 패널 표시 상태가
달라져도 선택, 검색어, 필터, 편집 초안은 유지합니다.

### 알려진 차이

이전 문서에는 있었지만 Swift 구현에 아직 없는 동작입니다. 구현하거나 기준에서 빼는 결정은 STA-101에서 다룹니다.

- 목록에 포커스가 있을 때 Return으로 선택한 Drop의 편집 맥락(인스펙터)으로 이동하는 동작
- 노트 저장 상태 변화와 태그 중복 안내를 VoiceOver에 공손한 라이브 알림으로 전하는 동작(지금은 화면 문구만 바뀜)

## 새 UI 점검표

새 화면, 섹션, 컨트롤을 추가하거나 바꾼 뒤 아래를 확인하고, 결과를 작업 이슈에 남깁니다. 기존 기능 시나리오는 다음 섹션의
`V-` 항목을 씁니다.

- [ ] **배치·피드백**: "새 요소의 배치와 피드백" 표의 자리와 방식을 따랐다.
- [ ] **시스템 값**: 코드에 hex 색, 고정 글꼴 크기, 직접 그린 컨트롤이 없다. 브랜드 색은 에셋 카탈로그의 이름 있는 색만 쓴다.
- [ ] **공통 컴포넌트**: "공통 컴포넌트" 표에 있는 패턴을 다시 만들지 않고 그 컴포넌트를 썼다. 레이아웃 치수는 `LayoutMetrics`, 반경은 `Radius`를 쓴다.
- [ ] **간격**: 모든 간격이 `Spacing` 토큰이고 역할 표에 맞는다. 숫자를 직접 쓴 곳은 주석이 있는 시각 정렬 보정뿐이다.
- [ ] **문구**: 사용자에게 보이는 모든 문구가 [문구 사전](swift-migration/strings.md)과 `StringTable.swift`에 `ko`·`en` 함께 있고
  `L10n.t`로 읽는다. 한국어와 영어 모두에서 잘리거나 넘치지 않는다.
- [ ] **아이콘**: SF Symbols를 쓰고, 새 의미면 [구현 명세 5장](swift-migration/spec.md) 표에 추가했다. 아이콘만 있는 버튼에 `Label` 문구와 `.help`가 있다.
- [ ] **스크롤**: 새 `ScrollView`·`List`·`TextEditor`에 `.slimScrollers()`를 붙였다.
- [ ] **테마**: 라이트·다크·시스템 테마에서 읽을 수 있다.
- [ ] **접근성 설정**: '대비 증가', '투명도 줄이기'에서 읽을 수 있고, 직접 만든 이동 전환은 '동작 줄이기'에서 멈춘다.
- [ ] **VoiceOver**: 모든 컨트롤에 이름이 있고, 상태(선택·열림·오류)를 색 말고도 문구나 특성으로 알린다.
- [ ] **키보드**: 키보드만으로 도달·실행할 수 있고, 새 단축키가 기존 단축키나 텍스트 편집 키와 겹치지 않는다.
- [ ] **한글 입력**: Return·쉼표로 동작하는 텍스트 입력은 한글 조합 확정 키에 반응하지 않는다(`CompositionMonitor`).
- [ ] **창 너비**: 960 pt와 1176 pt 경계(인스펙터 옆·오버레이)에서 배치가 깨지지 않는다.
- [ ] **상태 보존**: 패널을 접거나 창 크기를 바꿔도 새 화면의 입력 중인 값이 남는다.
- [ ] **저장 형식**: Drop 폴더와 `settings.json` 형식을 바꾸지 않았다. 바꿔야 하면 [구현 명세](swift-migration/spec.md)를 먼저 고친다.

| `V-03` | 창 크기를 바꿉니다. 960, 1050, 1176, 1280, 1440 pt에서 패널 배치와 검색 아이콘 전환을 확인합니다. 사이드바 선택은 유지되고 공간이 부족한 인스펙터만 오버레이로 열려야 합니다. Escape로 닫은 뒤 Drop 목록으로 포커스가 돌아와야 합니다. | 반응형 레이아웃·포커스 |
| `V-04` | Drop을 선택하고 검색·필터·편집을 한 뒤 패널을 접고 다시 엽니다. 선택, 검색어, 필터, 노트 초안, 태그 초안과 칩이 유지되어야 합니다. | 편집 상태 보존 |
| `V-05` | 빈 Library, 검색 결과 없음, 로딩, 스캔 오류를 확인합니다. 각 상태에 서로 구별되는 읽을 수 있는 안내가 있고 키보드 포커스를 계속 사용할 수 있어야 합니다. | 검색·목록 상태 |
| `V-06` | 텍스트 Drop과 이미지 Drop을 엽니다. 본문은 메인 영역에 남고 이미지 비율이 유지되며 접근성 레이블이나 오류 대체 레이블이 있어야 합니다. | 본문 패널 |
| `V-07` | 긴 앱 이름, 윈도우 제목, URL, 파일 경로와 누락된 출처 값을 확인합니다. 상세 정보가 넘치지 않고 긴 값은 읽을 수 있으며 없는 값은 표시하지 않아야 합니다. 앱 아이콘이 없으면 유형 심볼을 표시합니다. | 출처 요약·상세 정보 |
| `V-08` | 노트를 편집하고 자동 저장을 기다린 뒤 포커스를 옮깁니다. 저장 실패도 만들어 텍스트 유지, 상태 안내, 재시도를 확인합니다. | 노트 편집기 |
| `V-09` | Return, 쉼표, 추가 버튼으로 태그를 등록합니다. 중복·대소문자 변형·선행 `#`, 한글 조합 중 Return, 칩 삭제, 입력 포커스 유지를 확인합니다. | 태그 편집기 |
| `V-10` | Tab, 목록 화살표, `Cmd+F`, 패널 토글, 출처 상세 열기를 키보드로 실행합니다('전체 키보드 접근' 켬·끔). 포커스 표시와 접근성 이름을 VoiceOver로 확인합니다. | 키보드·접근성 |
| `V-11` | 라이트·다크·시스템 테마에서 '투명도 줄이기', '대비 증가', '동작 줄이기'를 켭니다. 대비 기준을 유지하고 재질은 불투명해지며, 동작 줄이기 중 인스펙터 오버레이가 미끄러지지 않아야 합니다. | 테마·접근성 |
| `V-12` | Settings와 캡처 팝업에 공통 토큰과 컨트롤 상태만 적용했는지 확인합니다. 새 Settings 항목은 "Settings 항목 추가" 규칙을 따르고, 화면 전체나 팝업 배치는 바뀌지 않아야 합니다. | 공통 컨트롤 범위 |
| `V-13` | 패널 너비를 끌어 바꾸고 재실행합니다. `settings.json`의 `paneWidths`가 복원되고, 창 축소만으로는 바뀌지 않아야 합니다. Drop 모델과 기존 저장 폴더 형식은 유지되어야 합니다. | 설정·저장 호환성 |
