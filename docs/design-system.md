# plopcut 디자인 시스템

이 문서는 plopcut의 논리 레이아웃 값, 시각 토큰, 컴포넌트 동작과 상태, 접근성, 검증 기준을 정의합니다. 확정 시안과 현재 구현
차이는 [`Design.md`](../Design.md)를 참고합니다.

아래 수치는 모두 plopcut의 구현 기준입니다. Apple 공식 디자인 토큰이 아니며 참고 이미지에서 측정한 값도 아닙니다. 레이아웃에는
CSS 논리 픽셀을 사용하고 생성 이미지의 픽셀 크기를 CSS 크기로 환산하지 않습니다.

## 레이아웃 및 간격

검색의 축약 기준은 앱 창의 CSS 픽셀 너비이며 패널 배치는 실제 콘텐츠 너비로 계산합니다. 참고 이미지는 패널 관계를 보여 주고, 다음 토큰은 구현 가능한 크기를
정의합니다.

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `space-unit` | 4 px | 기본 간격 단위 |
| `space-2` | 8 px | 작은 컨트롤과 행 간격 |
| `space-3` | 12 px | 가까운 요소 묶음 |
| `space-4` | 16 px | 기본 컴포넌트 간격 |
| `space-6` | 24 px | 본문 여백 |
| `space-8` | 32 px | 큰 섹션 간격 |
| `layout-sidebar-width` | 220 px | 펼친 사이드바 너비 |
| `layout-library-width` | 330 px | 기본 Drop 목록 너비 |
| `layout-inspector-width` | 280 px | 펼친 정보 인스펙터 너비 |
| `layout-content-min-width` | 360 px | 본문 최소 너비 |
| `layout-sidebar-inset` | 8 px | 창 가장자리와 인셋 사이드바 간격 |
| `layout-toolbar-clearance` | 64 px | 콘텐츠와 오버레이의 네이티브 도구 막대 예약 여백 |
| `layout-splitter-hit-area` | 8 px | 패널 구분선의 포인터·키보드 영역 |

### 반응형 레이아웃 및 패널 상태

Library는 서체관리자.app에서 관찰한 인라인 사이드바와 축약 검색 동작을 따릅니다.
창의 최소 너비는 960 CSS px이며, 사이드바를 너비 구간만으로 접지 않습니다.

- 앱 실행 시 사이드바를 펼칩니다. 사용자의 접힘 선택을 창 크기 변경과
  Library/Settings 왕복 중 유지합니다. Settings에서는 기존 탐색을 위해
  사이드바를 표시하고, Library로 돌아오면 이전 선택을 복원합니다.
- 사이드바를 접으면 목록과 본문이 빈 공간을 사용합니다. 펼친 사이드바는
  항상 본문 옆에 배치하며 오버레이로 표시하지 않습니다.
- 실제 콘텐츠 영역에서 사이드바, 목록 최소 300 px, 본문 최소 360 px,
  구분선 두 개 각 8 px, 인스펙터 280 px가 들어가면 인스펙터를 옆에 둡니다.
  기본 사이드바 220 px일 때 필요한 너비는 1176 px입니다.
- 공간이 부족하면 인스펙터를 접습니다. 토글로 도구 막대 아래 우측
  오버레이를 열고 같은 토글이나 Escape로 닫으며 토글로 포커스를 돌립니다.
  펼침을 선택한 인스펙터는 공간이 확보되면 다시 본문 옆에 표시합니다.
  사용자가 옆에 있는 인스펙터를 직접 접으면 그 선택을 유지합니다.
- 사이드바와 목록의 표시 너비를 가용 공간에 제한합니다. 창 크기 변화로
  저장된 사용자 너비를 덮어쓰지 않습니다. 패널 구분선의 입력 범위와
  접근성 값은 실제 표시 너비를 사용합니다.
- 1050 px 미만에서 상단 검색은 아이콘입니다. 클릭 또는 `Cmd+F`로 검색
  입력을 열고 포커스합니다. Escape는 입력을 닫지만 검색어와 결과를
  유지합니다. 지우기 버튼은 검색어를 비우고 전체 결과를 다시 표시합니다.

패널을 접거나 창 크기를 바꿔도 선택한 Drop, 검색어, 필터, 노트·태그의
편집 초안을 유지합니다. 접힌 패널 컨트롤은 Tab 순서에서 제외합니다.
패널 상태는 실행 중 표시 상태이며 새 영구 설정이나 Drop 저장 형식을
추가하지 않습니다.

## 색상 및 재질 토큰

앱의 테마 선택을 네이티브 창에도 전달해 AppKit 도구 막대와 본문의 색상을 맞춥니다.
시스템 테마로 돌아가면 네이티브 창의 테마 재정의를 해제합니다.

다크 시안을 시각 기준으로 삼고 라이트·다크 의미 토큰을 함께 정의합니다. 시스템 테마는 macOS의 라이트·다크 설정을 따르며, 사용자가
라이트 또는 다크를 직접 고르면 시스템 설정을 덮어씁니다.

| 의미 토큰 | 라이트 | 다크 | 용도 |
| --- | --- | --- | --- |
| `color-canvas` | `#F4F5F7` | `#16181C` | 상단과 본문이 공유하는 불투명 바탕 |
| `color-surface` | `#FFFFFF` | `#202329` | 편집기와 컨트롤의 단색 바탕 |
| `color-surface-muted` | `#E9EDF2` | `#292E35` | 보조 면과 호버 대체 바탕 |

본문 전체는 도구 막대와 같은 불투명 바탕을 사용합니다. 별도 도구 막대 배경 띠나 아래 선은 두지 않습니다. 배경 흐림은 사이드바와 개별 도구
컨트롤에만 적용하고, 인스펙터는 본문 바탕과 같은 색에 절제된 경계만 사용합니다. 사이드바 재질은 텍스트가 읽히는 수준으로 제한하고, 텍스트가
많은 면에는 투명도가 높은 유리를 사용하지 않습니다. 호버·포커스·눌림 상태에서는 개별 도구 컨트롤 재질을 더 선명하게 표시합니다.

사이드바 재질에는 16 px, 도구 컨트롤에는 8 px 배경 흐림을 사용합니다. 투명도 감소 또는 대비 증가가 켜지면 흐림을 끄고 반투명 면을
해당 의미 토큰의 불투명 색으로 바꾸며 경계를 강화합니다. 흐림 없이도 텍스트와 아이콘을 읽을 수 있어야 합니다. 재질을 탐색·제어 영역과
콘텐츠 영역에 구분해 쓰는 근거는
[Apple 재질 지침](https://developer.apple.com/design/human-interface-guidelines/materials)을 참고합니다.

## 타이포그래피

플랫폼 시스템 글꼴을 사용하고 한글 대체 글꼴 선택은 운영체제에 맡깁니다. 파일 경로, 필요한 URL, 단축키 표기에는 시스템 고정폭 글꼴을
사용합니다.

- UI 글꼴: `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
- 고정폭 글꼴: `ui-monospace, SFMono-Regular, Menlo, monospace`

| 토큰 | 크기 / 행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `type-caption` | 11 / 16 px | 400–500 | 시각, 조용한 메타데이터 |
| `type-label` | 12 / 17 px | 500–600 | 필드·섹션 레이블 |
| `type-body` | 14 / 20 px | 400 | 컨트롤과 보조 문구 |
| `type-content` | 16 / 24 px | 400 | 읽기 편한 Drop 본문 |
| `type-title` | 24 / 32 px | 600 | Drop 제목 |
| `type-section` | 13 / 18 px | 600 | 인스펙터 섹션 제목 |

작은 레이블에는 중간 또는 굵은 글꼴을 사용합니다. 선택, 오류, 저장 상태를 색상만으로 전달하지 말고 텍스트, 형태, 접근 가능한 이름이 있는
아이콘을 함께 사용합니다.

## 포커스, 모션 및 접근성

모든 키보드 포커스에 보이는 외곽선을 제공합니다. 일반 바탕에서는 강조색 외곽선을, 파란 선택 행에서는 전용 흰색 외곽선을 사용합니다. 호버
피드백은 선택과 포커스보다 약하게 표시합니다. 비활성 컨트롤은 흐린 바탕과 레이블, 네이티브 비활성 동작을 함께 사용합니다. 투명도만으로 비활성
상태를 나타내지 않습니다.

WCAG AA 대비를 충족합니다. 일반 텍스트는 최소 4.5:1, 큰 텍스트 (일반 18 pt 이상 또는 굵은 14 pt 이상)은 최소 3:1,
의미 있는 컨트롤 경계와 아이콘은 최소 3:1을 유지합니다. 각 테마와 반투명 면의 실제 배경에서 대비를 확인합니다. 대비 증가 설정에서는
불투명 면과 더 선명한 외곽선을 사용합니다. 이 기준은 plopcut 구현 목표이며 Apple이 정한 토큰 값이라는 뜻이 아닙니다.

| 모션 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `motion-quick` | 120 ms | 호버·눌림 피드백 |
| `motion-standard` | 180 ms | 작은 상태 변화 |
| `motion-panel` | 220 ms | 패널 오버레이 표시 |

탄성 효과 없이 표준 감속 곡선을 사용합니다. 동작 감소가 켜지면 패널 슬라이드와 장식용 이동 효과를 제거하고 최종 상태를 바로 표시합니다.
투명도 감소가 켜지면 배경 흐림을 끄고 의미 토큰의 불투명 색을 씁니다. 모션이나 투명도만으로 전달하는 정보는 두지 않습니다. 자세한 기준은
Apple의
[모션 지침](https://developer.apple.com/design/human-interface-guidelines/motion)과
[접근성 설정 테스트 지침](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app)을 참고합니다.

## 컴포넌트 동작과 상태

다음 표는 Library 컴포넌트의 기본·호버·포커스·선택·비활성·로딩·오류 처리를 정의합니다. 컴포넌트가 직접 소유하지 않는 상태는 해당
영역에서 안내합니다.

| 컴포넌트 | 기본·호버·포커스 | 선택·비활성·로딩 | 오류 및 접근성 |
| --- | --- | --- | --- |
| `WindowToolbar` 컨트롤 | 기본은 캔버스 위의 절제된 개별 재질을 씁니다. 호버는 재질을 선명하게 하고 키보드 포커스는 외곽선을 표시합니다. | 패널 토글은 `aria-expanded`와 `aria-controls`로 열림 상태를 알립니다. 비활성 동작은 읽을 수 있게 유지합니다. 캡처·새로 고침 로딩에는 진행 표시와 레이블을 함께 둡니다. | 명령 오류는 기존 상태 영역에 텍스트로 표시하고 접근성 알림을 보냅니다. 아이콘 단독 컨트롤에 현지화된 이름과 툴팁을 제공합니다. |
| `SidebarItem` | 유형·태그·Settings 행은 32 px 높이와 `18px 1fr auto` 격자를 공유하고, 섹션 제목은 아이콘 없는 12 px 텍스트입니다. 선택 행은 항상 하나입니다. 기본은 중성색, 호버는 절제된 채움, 포커스는 외곽선으로 표시합니다. | 현재 Library 보기나 필터는 활성 창에서 파란 선택 상태, 비활성 창에서 중성 선택 상태와 프로그램상 현재·눌림 상태를 함께 사용합니다. 비활성 레이블은 읽을 수 있어야 합니다. 로딩은 목록 영역이 표시합니다. | 필터 오류는 목록 영역에 표시합니다. 선택 상태를 색상만으로 전달하지 않습니다. |

### 노트 편집기

기존 600 ms 디바운스와 포커스 이탈 저장을 유지합니다. 편집기가 대기 상태일 때 안내 문구 “자동 저장”을 계속 표시합니다. 편집 후에는
`변경됨`, 저장 중에는 `저장 중`, 성공 후에는 다음 편집 또는 선택 Drop 변경까지 `저장됨`을 표시합니다. 저장 중에도 입력
필드를 편집할 수 있습니다.

저장 실패 시 입력 텍스트를 유지하고 `저장 실패`, 오류 사유, `다시 시도` 동작을 표시합니다. 저장이 성공할 때까지 사용자의 텍스트를
지우거나 바꾸지 않습니다. 상태 변경은 공손한 라이브 알림으로 전달하되 매 입력마다 알리지 않습니다. 저장이 진행 중일 때 새 편집이 들어오면
일반 디바운스에 따라 최신 값을 저장합니다.

### 태그 편집기

등록 전 초안과 등록된 칩을 분리합니다. Enter, 쉼표, 추가 버튼은 같은 등록 동작을 호출합니다. 한글 입력기 조합 중에는 Enter로
등록하지 않습니다. 조합 중인지 `isComposing` 또는 플랫폼 조합 키 신호로 확인합니다. 등록 값은 기존
`parseTags` (legacy) 경로로 정규화합니다. 빈 초안은 무시하고 중복은 새 칩을 만들지
않은 채 “이미 추가됨”을 공손하게 알립니다. 등록에 성공하면 초안을 비우고 입력에 포커스를 유지합니다. 칩 삭제 뒤에도 입력으로 포커스를
돌립니다. 저장 실패 시 초안과 칩을 유지하고 노트 편집기와 같은 재시도 경로를 제공합니다.

태그 정규화는 프런트엔드의 `drop-utils.ts` (legacy)와 백엔드의
`storage.rs` (legacy)를 따릅니다. 프런트엔드 규칙은 공백 제거, 선행 `#` 한 개
제거, 소문자화, 빈 태그 제외, 입력 순서를 유지한 중복 제거입니다. 현재 Rust `normalize_tags`는 선행 `#`을 모두
제거합니다. 일반 입력은 같은 방식으로 정규화되지만 반복된 `#`에서 차이가 있으므로 칩 구현 시 두 경로를 일치시킵니다. 이번 문서
작업에서는 계약이나 저장 데이터를 변경하지 않습니다.

## 키보드 및 패널 포커스

검색에는 기존 `Cmd+F`를 유지하고 Drop 목록에서 위·아래 화살표로 항목을 선택합니다. 목록에 포커스가 있을 때 Enter는 선택한
Drop의 편집 맥락으로 이동합니다. Tab은 화면에 보이는 도구 막대, 탐색, 검색·목록, 본문, 인스펙터 컨트롤 순서로 이동하며 숨겨진
컨트롤은 포커스 순서에서 제외합니다.

패널 토글은 항상 접근할 수 있어야 합니다. 오버레이가 도구 막대나 자기 토글을 가리지 않게 합니다. Escape는 열린 오버레이를 닫고 연
토글로 포커스를 돌립니다. 패널 표시 상태가 달라져도 선택, 검색어, 필터, 편집 초안은 유지합니다.
