# Domain docs

This repository uses a single-context domain documentation layout:
`GLOSSARY.md` at the root and decisions under `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs relevant to
the task. If they do not exist, proceed silently. Domain-modeling work
creates them when terms or decisions are resolved.

Use glossary terms in issue titles, specifications, code, and tests.
When a concept is missing, check the project's existing language before
proposing a glossary addition.

If a proposal conflicts with an ADR, identify the decision and explain
why it needs to be reconsidered.
